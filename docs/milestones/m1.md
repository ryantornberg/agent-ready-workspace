## The eval recorded again

On 2026-11-16 the maintainer approved criterion 29's revision and a new recording, to fix the harness defects the red team found. The work ran on the branch `m1/eval-rerecord`, at the driver tier, under [changing the machinery](../changing-the-machinery.md).

**What was built.** Each change has a test in `tests/test_core.py` (`EvalRerecordTests`); all ten failed at the base commit, `d38e712`, and pass at the tip. The three new `eval_record` cases failed there too.

- Criterion 29 as revised. A run counts when it passes every grader. Per case, the guided arm needs more such runs than the bare arm; pooled across the records that pass, it must beat the two-line arm by a one-sided Fisher exact test at p < 0.05. `pool.py` now uses the gate's own Fisher function.
- The red team's harness findings 1, 2, 4, 5, 8 and 12: the report grader, the output tail, the hook's code in the hash, ignored scaffold files, the temporary folder, the timed-out run. And the `__pycache__` defect from slice 3, with the harness's own git calls no longer reading the operator's git config or global ignore file.
- `AGENTS.md`: the eval rule now names the two-line instruction. It was edited before the recording, so the recording covers it.

**How "the fair rule" for the report grader was read.** The definition of done and the two lines both ask that claims be marked verified or inferred. So a claim counts as marked when "verified" stands as a label, not as a verb: at the start of a line, in emphasis, code, brackets or parentheses, before a colon, or after a dash. "Not verified:" and "unverified" do not count. The rule was written, tested and committed before any run, and is one regular expression shared by every case and every arm. Applied to the earlier recording, it moved only the two-line arm's three fix-a-bug misses, the ones the red team found.

**What the checks caught.**

- One fix round: the first version of the scaffold test left `README.md` out of its comparison, because the other session's edit appends to it.
- The pre-run commit used `--no-verify`, as the machinery page's trap says: `check --staged` showed only the three `eval_record` findings, and the message check was run by hand. Before the recording, seven older tests that read the records failed, as expected; after it, all pass.
- A shell slip recorded a list of paths as one path in the working copy's ledger. It was removed by hand, before any commit.
