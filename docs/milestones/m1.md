What the checks and the red team caught in slice 0:

- **The session locked itself out.** A change to the `deny_list` part made two of its old cases fail before the cases file was updated. Every hook call loads every part, so every shell and edit call was then refused, including the repair. The maintainer repaired it from their own terminal. This is the self-lock that slice 2 removes.
- **A part was skipped without a word.** The commit check did not run `deny_list` while the manifest that adds it was unstaged, because the staged manifest decides. Slice 2's required-parts rule covers this.
- **A unit test's sample terms matched text in the part's own cases file.** The test now uses different terms.
- **The red team found ten problems in slice 0 and this plan.** All are triaged in the plan's [red team](../plans/m1-make-the-core-hold-weight.md#red-team) table.

What the checks caught in slice 2:

- **A fail-open in the first build.** Hook calls skipped a hook whose `EVENT` was misspelt, instead of refusing. An existing test caught it. A hook whose event is unreadable or unknown now loads, and so refuses.
- **Two cases expected a warning without saying so**, in `freshness` and `deny_list`. Once a plain expectation meant an error, they failed. Both now state the warning level.
- **Found on the way, left alone:** in a linked git working copy, `.git` is a file that holds the main checkout's absolute path. `check` reads it, and `deny_list` matches the home-folder path, while `check --staged` does not see it. This belongs with criterion 17 in slice 4.
- **The slice was built in a separate working copy**, so the session's own hooks ran the old code while it worked. The new hook behaviour was then run live in the main checkout before the commit.
