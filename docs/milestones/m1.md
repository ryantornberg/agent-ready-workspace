What the checks and the red team caught in slice 0:

- **The session locked itself out.** A change to the `deny_list` part made two of its old cases fail before the cases file was updated. Every hook call loads every part, so every shell and edit call was then refused, including the repair. The maintainer repaired it from their own terminal. This is the self-lock that slice 2 removes.
- **A part was skipped without a word.** The commit check did not run `deny_list` while the manifest that adds it was unstaged, because the staged manifest decides. Slice 2's required-parts rule covers this.
- **A unit test's sample terms matched text in the part's own cases file.** The test now uses different terms.
- **The red team found ten problems in slice 0 and this plan.** All are triaged in the plan's [red team](../plans/m1-make-the-core-hold-weight.md#red-team) table.

What the checks caught in slice 2:

- **A fail-open in the first build.** Hook calls skipped a hook whose `EVENT` was misspelt, instead of refusing. An existing test caught it. A hook whose event is unreadable or unknown now loads, and so refuses.
- **Two cases expected a warning without saying so**, in `freshness` and `deny_list`. Once a plain expectation meant an error, they failed. Both now state the warning level.
- **Found on the way, left alone:** in a linked git working copy, `.git` is a file that holds the main checkout's absolute path. `check` reads it, and `deny_list` matches the home-folder path, while `check --staged` does not see it. This belongs with criterion 17 in slice 4.
- **The slice was built in a separate working copy**, so the session's own hooks ran the old code while it worked. Before the push, the new behaviour was run live in the main checkout. With a `links` case broken, the session's shell calls still ran while `check` refused. With a `no_stage_all` case broken, shell calls were refused, and the edit tool repaired the case.

What the checks caught in slice 1:

- **The attacks, before the fix.** At the base commit, seven of the eight unreadable payloads were allowed, among them an empty event, a `filePath` field and a `cmd` field. So were an upper-cased absolute path into the shelved folder and a relative path through a symbolic link into it. With no Python on the path, the wiring exited 127, which the agent tool does not treat as a refusal. At the slice's tip each of these is refused, and a test in `tests/test_core.py` (`FailClosedTests`) holds each one.
- **One fix round.** A path holding a NUL character was allowed by the first build, because the path library resolved it without complaint. The criterion 7 test caught it. The runner now refuses such a path.
- **Criterion 11, as read here.** "Where the tool exposes that setting" is read strictly. When the tool lets a task set a model or an effort, a task that leaves it unset is refused, because the helper would inherit the calling session's value and nothing would say what it runs at. Allowing an unset value would make the check pass by omission. Changing this is one line in `parts/handoff_tier.py` and one case.
- **Found on the way, left alone:** the same linked-working-copy `.git` finding that slice 2 recorded. Slice 1 was also built in a separate working copy, where `check` reports it. The checks were run in the main checkout before the push.

What the checks caught in slice 5:

- **The attacks, before the fix.** At the base commit, the before-shell hook refused `git commit -m"add export handler"`, because it read the attached message as the flag `-a`. It refused `git add -u docs/parts.md`, which names its path, and `git add .` in a scratch repository outside the workspace. A script that ran `git add -A && git commit` swept another session's edit into the commit, and the commit passed. A commit message, an author email or a committer email holding a deny-listed term was committed. At the slice's tip the three commands are allowed, the sweep is refused at the commit, and the three commits are refused by the new commit-msg hook. A test in `tests/test_core.py` (`StagingAtTheCommitTests`) holds each one.
- **How "the shell hook stays as an early reminder" was read.** The hook no longer refuses. It reminds, and the commit check enforces; [decision 0002](../decisions/0002-hooks-remind-the-commit-enforces.md) gives the reasons. Keeping the refusal would have needed the parser to learn which repository a command acts on, to allow `git add .` in a scratch repository, which is the growth the plan replaces. Four existing tests asserted that the hook refuses `git add -A`. They now assert the reminder, and each kept its other assertions.
- **A gap in the first build, closed.** Only the edit tools fill the ledger, so a session that wrote its files only through the shell never opened one, and `git add -A` then committed whatever was in the folder. A reminder from the shell hook now also opens the ledger, even empty, so that commit is compared too, and the session records its shell-written files by name.
- **Three fix rounds.** Hook scripts copied into a test fixture were not executable, so git skipped them and every sweep was committed. A test wrote a file into a folder it had not created. The ledger's rewrite used an argument that Python 3.9 lacks, which the partial-commit test caught on the local Python 3.9. A test of the message check staged the manifest without its parts, so the runner refused before it checked anything.
- **Kept out of this repository's ledger.** One older test ran the wiring on this repository with an allowed edit to `README.md`, which would now open the developer's own ledger. It edits a scratch file instead, and the test module fails if any test changes `.git/ws-ledger`.
- **The eval grades did not move.** The grader calls the same `no_stage_all` function, whose parser now sets option values aside. Re-grading the ten stored transcripts gave the same result at the base commit and at the tip.
- **Found on the way, left alone:** the linked-working-copy `.git` finding from slices 2 and 1. The checks were run in the main checkout before the push.
- **The live run in the main checkout.** The slice was built in a separate working copy. Before the push, the main checkout was moved to the slice's tip, so the session's own hooks ran the new code. A `git add .` in a scratch repository went ahead, and the reminder reached the agent next to the result. An edit to the shelved folder was refused and not recorded. This edit, made in the separate working copy, was recorded in that working copy's ledger, not the main checkout's. Its commit then passed the ledger comparison, and the post-commit hook closed the ledger.
- **A cost the live run showed.** The agent tool reports the folder the session started in, not the folder a command moves to. So the scratch-repository command opened the main checkout's ledger, empty, and a person's next commit there would have been refused until the ledger was closed. It was closed after the run. Decision 0002 lists this under what the change gave up. A follow-up change, after slice 5 merged, opens the ledger only when that working copy has uncommitted changes, since a clean one has nothing of anyone's to sweep. Its test, in `StagingAtTheCommitTests`, failed before the change and passes after it.

What the checks caught in slice 4:

- **The attacks, before the fix.** At the base commit, each of the nine tests in `tests/test_core.py` (`AdoptionPathTests`) failed. A code repository under `src/` with its own broken links failed both `check` and `check --staged`. Pages in Windows-1252 and UTF-16 were reported only as "not valid UTF-8", and freshness skipped them without a word. `symbols.py` did not find a type declared in a Windows-1252 file. On a copy of this repository, `check` failed and `check --staged` passed with a stray `.DS_Store` or a `.pytest_cache` folder in the eval scaffold, because the eval hash took in files git ignores. A symbolic link to a page failed the commit check only, because the commit holds the link's target path while the folder check read the page. A deny-listed term in a staged file under `node_modules/` passed both. In a linked working copy, `check` failed on the `.git` file. On a repository of 3,000 notes, `check --staged` started 6,091 git processes, one per file read. `AGENTS.md` and `INDEX.md` carried no review date. A name in `AGENTS.md` that the code no longer defined passed. A page dated one day ahead of today in UTC failed. At the slice's tip all nine pass.
- **How "workspace-owned" was read.** A page inside a code repository under the workspace is not read by the page checks. Git decides what a code repository is: a submodule, or an untracked folder holding its own `.git`. No folder setting is needed, and a workspace page under `src/` is still checked. A link from a workspace page into a code repository still resolves.
- **How "reported" was read.** A page that is not UTF-8 is an error from each page check that covers it, naming the encoding: `links` and `freshness` each say what they could not read. Code is read in UTF-8, UTF-16 or Windows-1252, so `aliases` and `symbols.py` find names there. The eval hash is unchanged for UTF-8 files; a file it cannot read is now named as unreadable, not as missing.
- **How "agree" was read.** Both snapshots start from one `git ls-files` call. A tracked or staged file is always listed, under `node_modules/` too, and `.git` never is. `check` adds the untracked files git does not ignore. `.DS_Store` is in `.gitignore`, and pytest's cache ignores itself. A symbolic link reads as its target path in both, as git stores it, and the page checks skip it. A side effect: `check` no longer reads an untracked file that git ignores, so the deny list does not scan files that cannot reach a commit.
- **How "names in the contract" was read.** `aliases` takes a backticked word in `AGENTS.md` when it mixes upper and lower case, such as `AccountFreeze`. Every backticked identifier was rejected as the rule: `main`, `KIND` and `max_age_days` are not code names, and would have failed the contract.
- **How "one day ahead of UTC" was read.** `freshness` takes today's date in UTC and accepts a date up to one day later, since no time zone is more than a day ahead of UTC. A case's `today` is a date in UTC.
- **Three git processes.** `check --staged` lists the index once, compares it with the last commit once, and reads every staged file, plus the last commit's manifest, in one `git cat-file --batch`. The required parts now come from that batch, not from four more git calls.
- **One fix round.** A new `aliases` case expected a file path as message text, and `selftest` failed it.
- **The trap from slices 2, 1 and 5 is closed.** At the base commit, `check` in this slice's working copy failed on `.git:1` against the deny list. At the tip it passes there, and a test holds it.
- **The eval grades did not move.** Re-grading the ten stored transcripts gave the same result at the base commit and at the tip, and the eval hash still matches its record.

What the checks caught in slice 6:

- **The attacks, before the fix.** At the base commit, each of the twelve criterion tests in `tests/test_core.py` (`ShapeForGrowthTests`) failed. `python3 ws.py --version` was an unknown option. A manifest with any version, or none, loaded. `--phase` was an unknown option, and a check's `PHASES` was ignored. A manifest entry with no `why`, an unknown top-level key such as `tier`, and a tier binding that lacked a model or an effort all loaded, and a task for the driver tier was allowed while the mechanical tier had no model. CI had no `permissions` block and no schedule. A 10,015-character line was parsed, and its link reported as missing. `new Order(1),` in a C# initializer was reported as a constructor. `ws.py` defined seven functions and `tools/symbols.py` one. At the slice's tip all twelve pass. A thirteenth test, that a missing `why` does not lock the hooks, passed its hook calls at the base and failed only because `check` did not refuse the entry.
- **The engine in one folder.** The runner's commands moved from `ws.py` to `wslib/runner.py`, and the lookup's command line from `tools/symbols.py` to `wslib/symbols.py`. Both files now only start the engine. [Decision 0003](../decisions/0003-the-engine-in-one-folder.md) gives the reasons and what was rejected, among them renaming `wslib/`.
- **How "the manifest's `version` must match" was read.** Exactly equal, and missing counts as different. Every command refuses a mismatch, hook calls included: a manifest written for another engine may mean something else by a setting, and a hook that misreads one could allow what it should refuse. The cost is that an agent cannot change the engine's version and the manifest's one at a time in the working copy its session runs in. The second change would be refused. Decision 0003 records this, and [changing the machinery](../changing-the-machinery.md#traps) says to make both changes in one step.
- **How "parts selectable by phase" was read.** A check declares its phases in its own file, as `PHASES`, from `commit`, `ci` and `nightly`; the default is commit and CI. A `phases` key in the manifest was rejected, because one manifest edit could then move `deny_list` off the commit, the attack the red team's finding 3 closed. `check` and `check --staged` run the commit phase, so they still agree. No part here is nightly yet.
- **How "the runner refuses" was read for hook calls.** A hook call refuses a version mismatch and an incomplete tier binding, because its answer depends on them. A missing `why` and an unknown key fail `list`, `selftest`, `check` and the commit, but not a hook call, so a half-finished entry cannot lock the session out. A test holds both halves. A manifest with no `tiers` at all still loads; `handoff_tier` then refuses every task.
- **How "reports" was read for the long line.** As an error, like a page that is not UTF-8: a line the reader skips must not pass in silence.
- **The weekly run.** It has no push to compare with, so it runs `check --phase ci` on the tree as it stands, then `check --phase nightly`. Comparing with nothing would treat every page as edited and fail any page past its review date, which is a different rule from the one `freshness` enforces.
- **The commit check caught this session.** Most files were written through the shell, and the first edit-tool write opened the working copy's ledger. The first commit was refused with twelve errors, one per staged file the edit tools had not written. The files were then recorded by name with `ledger --add`.
- **Two fix rounds.** The new `links` case was one character short of the limit, and `selftest` failed it. After the move, the lookup's command line still called `symbols.find` from inside `wslib/symbols.py`, and running it raised a `NameError`.
- **The eval grades did not move.** Re-grading the ten stored transcripts gave the same result at the base commit and at the tip, and the eval hash still matches its record.
- **The live run in the main checkout.** Before the push, the main checkout was moved to the slice's tip, so the session's own hooks ran the new code. With the `why` removed from the `links` entry, the next shell command ran and `check` refused the manifest; the edit tool then restored it. An edit to the shelved folder was refused. A delegated task naming no tier was refused. The version mismatch was not run live, because it would have locked the session out until the maintainer repaired it; the tests hold it. The main checkout's ledger, opened by the two manifest edits, was closed, and the checkout returned to `main`.
