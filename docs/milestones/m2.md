## Slice 0, the eval harness re-recorded

Built on the branch `m2/slice-0`, in a separate working copy outside the repository folder, at the driver tier, under [changing the machinery](../changing-the-machinery.md).

**What was built.** Each change has a test in `tests/test_core.py` (`EvalHarnessApartTests`). Seven of its eight tests failed at the base commit, `397e972`, and all eight pass at the tip. The eighth holds the harness's file listing and hash to the check's; it passed at the base too, and guards the new listing.

- `grade.py` loads the graded hook's own file, so `wslib/parts.py` left the eval hash. Only the hook's own file and the harness count. Neither `run.py` nor `grade.py` imports anything from `wslib/`. In a scratch copy, an added hook event and an edited snapshot module leave every record as it was (criterion 2).
- `leaks()` reads each transcript string instead of the JSON text, so a Windows path written with backslashes is found. The test runs on all three systems, and the Windows skip in the older temporary-folder test is gone (criterion 27).
- `eval_record` needs 40 or more runs in every arm, pooled across the cases (criterion 1). Its cases now hold 40-run records, and a new case shows 5 runs per arm failing.
- Git ignores `.claude/worktrees/` (criterion 28).
- `AGENTS.md` and `INDEX.md` were not edited. Nothing slice 0 changes is named there; what slices 1 to 5 add waits for slice 6's recording.

**How the work was saved before the paid runs.** The harness commit used `--no-verify`, as the machinery page's trap says and as the approval made standing. `check --staged` showed only the three `eval_record` findings, and the message check was run by hand.

**Results.** Recorded on `claude-haiku-5-5` with Claude Code 2.1.326, fifteen runs per arm in each case. Runs passing every grader, with the 95% Wilson interval:

| Case | Guided | Two-line | Bare |
|---|---|---|---|
| big-report | 15 of 15: 100% (80% to 100%) | 4 of 15: 27% (11% to 52%) | 0 of 15: 0% (0% to 20%) |
| fix-a-bug | 15 of 15: 100% (80% to 100%) | 15 of 15: 100% (80% to 100%) | 0 of 15: 0% (0% to 20%) |
| nightly-job | 15 of 15: 100% (80% to 100%) | 0 of 15: 0% (0% to 20%) | 0 of 15: 0% (0% to 20%) |
| **Pooled** | **45 of 45: 100% (92% to 100%)** | **19 of 45: 42% (29% to 57%)** | **0 of 45: 0% (0% to 8%)** |

Guided against two-line, one-sided Fisher exact test: p = 8.4e-11. Guided against bare: p = 9.6e-27. The eval did not lose. Every comparison M1's recording won still holds: guided beats bare in each case, and guided beats two-line in nightly-job, in big-report and pooled. [evals/README.md](../../evals/README.md#the-recorded-runs) has the per-grader table.

**Agent runs: 139 of the 150 allowed.** One probe run, which held on all nine points; three smoke runs, one per case on three different arms; and 135 recorded runs. No run failed to start, so none was repeated.

**Before the commit,** the transcripts passed the deny list through `check`, and the harness's own `leaks()` found nothing in any of the 135.
