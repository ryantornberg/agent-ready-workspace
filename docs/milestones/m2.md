# M2, port what the work workspace learned: milestone record

M2 brings the features the maintainer's work workspace grew for running several agent sessions at once into this one, rebuilt generic. The plan is [the M2 hand-off plan](../plans/m2-port-from-the-work-workspace.md), approved on 2026-11-16 with changes.

**In short:** M2 is signed off. Slices 0 to 6 and the walled reader are done, and the outside checks ran: the M1 attack scripts still hold, and a fresh red team found one blocker and ten other problems, fixed in [#20](https://github.com/ryantornberg/agent-ready-workspace/pull/20) or stated as limits. The eval harness no longer depends on the engine. The closing recording, after the index and contract edits, gave 40, 19 and 0 of 45 runs passing every grader, guided against two-line p = 2.5e-06; it passes the gate, but the guided arm slipped from slice 0's 45. Machinery can no longer reach main by a direct push or an administrator merge, each session gets its own browser, hooks follow a written contract with session events, a second writing session is sent to a worktree, and three doc checks hold the pages to their rules.

## Slice 1, direct-push and admin-merge refusals

Built on the branch `m2/slice-1`, in a separate working copy outside the repository folder, at the driver tier, from the walled reader's two descriptions.

**What was built.** Fourteen new tests failed at the base commit, `eb567e5`, and pass at the tip: `DirectPushTests` (12), `AdminMergeTests` (1) and `test_cases_bite` (1, one subtest per new part).

- `direct_push`, a check in a new `push` phase, run by a new pre-push hook through `ws.py check --push`. A push to main that adds a commit changing a machinery path is refused, naming the commit, its subject and the path (criterion 3). A doc-only push, a push to another branch and a deletion pass (criterion 4). A merge is judged by the commits it brings in. The part and its list come from the remote's current tip, so a push that drops paths from the list is judged by the old list. A range that cannot be listed, or a remote tip with no readable manifest, refuses a push to main. A test pushes through `git push` itself, with two refspec forms.
- `no_admin_merge`, a before-shell hook that refuses `gh pr merge --admin` in every form the cases name, and allows a merge without it and a quoted mention (criterion 33). It loads its command-line parser from `no_stage_all`'s file instead of editing that file, which the eval hash covers.

- Both new parts' messages name `docs/changing-the-machinery.md` (criterion 32), and a do-nothing stub fails at least one case of each (criterion 22).

**Decided while building.** The agent settings file counts as machinery as a whole. The source counted it only when its hook entries changed; slice 2 will change it for the browser setting, and that change belongs on a branch anyway. A new main is checked over its whole history, so a new repository's first push needs `--no-verify`; the machinery page says so.

## Slice 4, the writing-session lease

Built on the branch `m2/slice-4`, in a worktree under `.claude/worktrees/`, now that slice 3 places nested worktree paths, at the driver tier, from the walled reader's two descriptions.

**What was built.** `LeaseTests` (12) and the two new subtests in `test_cases_bite` failed at the base commit, `8a7ccca`, where `wslib/lease.py` did not exist, and pass at the tip.

- [Decision 0005](../decisions/0005-concurrent-sessions-and-the-edit-ledger.md): identity, liveness, acquire, takeover by state, release, and the fast-forward. The walled reader flagged that the source's takeover is by state and the plan's text read as by time; the decision takes the state rule, with the five-second minimum age.
- `wslib/lease.py` and the `lease` hook. A second live session's edit to a tracked file in the main copy is refused, naming the worktree command and the decision (criterion 14). Each takeover condition refuses on its own, and a dead holder or an old corrupt lease is replaced (criterion 15). A Claude Code payload and a Codex payload each take, keep and release a lease (criteria 16, 18). An untracked file and an edit in a linked worktree pass with no lease (criterion 31). Forty racing threads give one winner.
- `fast_forward` at session start: a main copy with nothing to protect moves to `origin/main` without a word; a tracked change or another live holder holds it back, and the session is told why; local commits are named and left alone; another branch, a linked worktree or an unreachable remote is left alone silently (criterion 17).

**Decided while building.** A process id like `1.5` is not a whole number, so it is dead; the first version read it as process 1, which the liveness test caught. Codex's process id is its hooks' grandparent, from slice 3's recording, and is read on POSIX only; the decision names this as the first thing to recheck.

**The fix after the merge.** Running the suite in the main checkout left `.git/ws-lease.json` behind. Two older wiring tests send an edit to the shelved folder through the real wiring; the runner gave each edit its lease before any hook decided, so the refused edit took the lease, under session "s" and the agent's own live process. While that lease looked live, this session's own edits could have been refused whenever the main copy had changes to protect. Now every other hook decides every file of a call before the lease is taken, `LeaseTests` has a case for it, and the test module fails when any test changes this repository's lease. It failed at `114f302` and passes at `0f59088`.

**CI:** all five jobs green on [#16](https://github.com/ryantornberg/agent-ready-workspace/actions/runs/44007443653), on [#17](https://github.com/ryantornberg/agent-ready-workspace/actions/runs/44008320844), and on [`main` after the fix](https://github.com/ryantornberg/agent-ready-workspace/actions/runs/44008807927).
