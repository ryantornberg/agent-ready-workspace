# M3, the reading layer, the safety machinery and the kit: milestone record

The record of the third milestone, written as its slices finish. The plan is [the M3 hand-off plan](../plans/m3-reading-layer-machinery-and-kit.md).

**In short:** M3's build is finished and both outside checks have run; sign-off waits for the maintainer's go. Every playbook and how-to now says whether it is proven, about 60 pages of procedures, templates and lane drafts are written fresh, 28 skill wrappers route to the procedures that can run today, and the kit can make and upgrade an instance. The safety machinery M2 lacked is in place: shell guards on force pushes, discards, outward writes, the git folder and secrets, a stop gate, `ws.py merge` and `with-secrets`, with cases and CI on three systems. R1 passed 41, 18 and 0 of 45 and R2 42, 18 and 0. The routed arm, which reads every shipped page and the wrappers, missed its margin twice and passed 40 of 45 after the maintainer's chosen fix. The private attack scripts found four blocking gaps; the two that let a push command rewrite main were fixed in [#57](https://github.com/ryantornberg/agent-ready-workspace/pull/57), and the rest wait for M4's parser work. The red team's ten findings are triaged in [its record](../records/adversarial-reviews/2026-11-25-m3.md). Every success criterion is met, 54 through the maintainer's decisions.

## Known limits, for M4

Each is open on main and stated in the README's Limits.

- **B3 and B4, the same cause as B1 (Q85).** Braces or a glob in a write path or a `git config` key reach into `.git` past `git_folder_shell`, such as `echo x > .gi?/config` or `git config {alias.p,!sh}`; in a write path they edit `outward-repos.json` past `outward_write`, such as `rm outward-repos.jso?`. They close with the parser work.
- **A zsh glob qualifier outside a push's own words.** zsh reads `x(e:'...':)` as a glob qualifier that runs code, where the parser reads a word and a subshell. So `ls README.md(e:'git push -f origin main':)`, an array assignment or a `for` list with such a word force-pushes main past every shell guard. The sign-off's instruction review found it; it is blocking by the review's rule, and the recommendation to the maintainer is to take it into M4 with the parser work.
- **Commands git itself runs.** Git can still reach main through a command it runs from its config, the environment or a URL: `GIT_EDITOR`, `core.editor`, `GIT_SEQUENCE_EDITOR`, `core.fsmonitor`, a difftool or mergetool `cmd`, `credential.helper`, `GIT_SSH_COMMAND`, the `ext::` transport, and `git bisect run`. The README names this as the interpreter limit.
- **The lines GFIX's re-check left (Q80, red team finding 6).** A quote inside `${...}` or `((`, runner text such as `flock /tmp/l -c '...'`, a shell, `env` or `printenv` named in another letter case, a shell the parser does not read, and a word of only `\0` under `sudo -s` or `sudo -i`.
- **The non-blocking routes the scripts found.** Discards `no_discard` does not judge, such as `git checkout-index -f -a`, `git update-ref`, path-scoped `restore` or `checkout`, and abbreviations such as `git reset --har`; reads of secrets `secrets_shell` does not see, such as `gh auth status --show-token`, `git credential fill`, the macOS keychain, a `cd` into a secrets folder before a plain read, and `/proc/*/task/*/environ`; `python3 ws.py ledger --close`, which an agent can run to empty its own ledger before it stops; and `gh api` calls that fork or copy a listed repository.
- **The pre-push hook (Q82, red team finding 7).** It loads each part's cases from the remote's tip and the library from disk, so a guard change that turns a passing case into a refusal is pushed with `--no-verify` after the commit checks pass.
- **The merge helper and stacked pull requests (Q84).** `python3 ws.py merge` deletes the merged branch, and GitHub then closes a pull request stacked on it.
- **Four wrappers still miss their fire case** in most selection runs: fix-a-bug, parts, research-ladder and safe-refactor (Q49).
