# M3, the reading layer, the safety machinery and the kit: milestone record

The record of the third milestone, written as its slices finish. The plan is [the M3 hand-off plan](../plans/m3-reading-layer-machinery-and-kit.md).

**In short:** sub-batch A is built and recorded, and slices B1, C1, C2, C7 and C3 are merged. The eval harness is generalized, every page names its kind and opens in one order, rules carry enforcement tags, and every playbook and how-to says whether it is proven. R1 gave 41, 18 and 0 of 45 runs passing every grader, within 3 of M2's 40, with no re-record. Sub-batch B's port ledger (B0) maps all 200 catalog items it must account for. B1's instruction review is merged: a guidance change names its review record in a commit trailer, checked at the commit, the push to main and in CI, and its first run left a record for each page sub-batch A wrote. B2 wrote four of its five batches: twenty-nine procedure, routing, review, workspace and provider pages, among them the playbook catalog, the how-to index, the review orchestrator and tracker and git-host operations. The stop rule stopped it after each, and again after batch 5's opening fix round on batch 4's pages; it waits for the maintainer's decision on how batch 5 resumes. C4 is merged: `python3 ws.py merge` merges on GitHub with a merge commit once CI passed on the head commit, and merged its own pull request; a push from the main working copy is refused while another session holds it. C5 confirmed that both agent tools offer the after-edit and stop events, then split into six slices with the maintainer's yes. C5a is merged: an edit to a path in an index chain shows the agent the rest of the chain, and a session that edited files is refused its first stop of a turn while the check or the fast tests fail. C5c is merged: an agent's write into a git folder or a git config file, and a `git config` change to a key the guards read, are refused, and the discard and push guards judge a git alias as what it runs. C5d is merged: a force push or a deletion of main is refused in every form the plan names, judged by what git would send; while another session holds the main copy, a worktree's push of its branch, of every branch, a mirror or a glob is refused; and `core.hooksPath` and a git alias that runs `git config` are refused. TFIX makes each hook call cheaper, so the macOS jobs meet the 200 ms budget: a hook call skips the cases of a hook that passed before on the same files. B3's two opening changes are on main: the instruction review marks each finding blocking or not, and procedure endings states once how a procedure ends, now pushing from a throwaway worktree when the main copy holds others' changes. B3's templates, records and standards are reviewed and fixed once on their branch; the re-check found blocking breaks the fixes made, so lane B's stop rule stopped B3 a second time. C5e is merged: an agent writes only to the repositories in the instance's list, `outward-repos.json`, which the guards keep agents' edits out of; elsewhere `gh` runs only its reads, and no agent approves or calls `gh api graphql` anywhere. C5f is merged: an agent's shell runs none of the common environment dumps and reads no secrets file, and `python3 ws.py with-secrets` hands a named value to one program and never to the shell. C6 is merged: a test shows that no guard on a tool call, a commit or a push turns off when one environment variable is unset, the deny list's opt-out aside, and that a killed commit check leaves nothing behind; no guard needed a fix. PSFIX is merged: the secrets hook no longer refuses the name of PowerShell's environment-variables method in a heredoc's text or a message, and still refuses every command that runs it. The rest of B3, slices B2t and B4 to B7, C5b, C8 and C9, slice Z and the outside checks are still to come.
