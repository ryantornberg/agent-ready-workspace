# M3, the reading layer, the rest of the safety machinery and the kit: hand-off plan

The plan for the third milestone: write fresh, in this repository, everything a person or agent reads in order to work, finish the safety machinery, and package the workspace as a kit an instance can adopt. Building sessions work from it; the maintainer approves it. It follows the [hand-off plan template](../templates/hand-off-plan.md).

**In short:** the work workspace holds about 60 core procedures, templates and record types, and machinery this repository lacks. This plan ports them in three sub-batches: the eval harness and the page structure first, with one recording; then the procedures, as pages marked proven or unproven; then the machinery and the kit. A closing slice makes the queued contract and index edits, records the eval once more, and measures whether the new pages harm what is proven.

## Key points

Third draft, after rounds 1 and 2 of the red team. Every accepted action of both rounds is applied to the body. The four choices that needed the maintainer's yes are settled (see "Settled decisions"), so only approval is left.

- **A playbook can now ship unproven, but says so.** Today every page in `docs/playbooks/` must have an eval case that beats the bare model. Of the about 60 pages this plan ports, about half are templates, record formats and tutorials, which checks and CI hold instead. About 29 are procedures an agent follows. Proving those now is not honest: cases must come from real tasks, this workspace has two milestones of them, and many procedures need machinery from M4 or M8 before they can run. Instead every procedure carries a `proof` field. A `proven` page needs a real-run record and a passing eval record; an `unproven` page is labelled as such where agents and people read it. The gate for proven pages gets stricter, not looser: each must beat the two-line arm on its own. Decision record 0006 sets this.
- **Unproven is temporary.** Each unproven page names the milestone that is to prove it, in a `prove-by` field. A check fails an unproven page once that milestone's record is signed off. Moving `prove-by` later is refused unless a failed proof attempt is on record. B2 sets each page's `prove-by` in a table: the milestone whose program section runs that procedure on real work, with M6 as the default for development procedures. The six procedures that may be model coaching get `prove-by: M4`, and the program's M4 carries their proof attempts.
- **Shipping unproven pages must not hurt what is proven.** M2 showed that added text can: a longer index dropped the guided arm from 45 to 40 of 45. The closing slice adds a fourth arm, "routed": the guided arm's files, every page the index routes to, and the skill wrappers every session loads. It must pass at least the guided arm's count minus 3, pooled across the three cases, or the plan stops. It is measured once, in a record the gate never reads, because a gate would make every doc edit cost a recording; the README says so.
- **The guided arm is also held to its own past.** A new recording whose guided arm passes more than 3 runs fewer, pooled, than the previous record, or than the record `fix-a-bug.md`'s `proven-by` names, fails. Today's gate cannot catch a slide like M2's 45 to 40. Comparing with both records stops small slides from adding up: 45, 42, 39 would pass a check against the previous record alone. The anchor is M2's closing recording (40 of 45), not M1's 44: anchoring at M1 would fail R1 for a slip M2 already recorded and published.
- **The margin tests can stop the plan on noise, so a miss is recorded once more.** At M2's rate of 40 of 45, a 45-run arm falls more than 3 short of an unchanged one about 12% of the time. On a margin miss, that arm is recorded once more, and the pooled 90 runs are judged at a margin of 6. Simulated at M2's rate with no real change, the chance that R1, R2 or the routed arm stops the plan falls from about 30% to about 15% (computed, 200,000 trials). That 15% is the false-stop rate this plan accepts.
- **The public sentence "a playbook stays only while it beats the bare model" stops being true as written.** In this repository it lives in the `eval_record` entry's `why` in `workspace.json`, the part's docstring and the README. Slice A3 changes each to "a playbook marked proven stays only while it beats the bare model", beside the README's count of proven and unproven pages. Pages outside this repository are out of scope.
- **Every harness change lands before the first recording.** The eval hashes the harness into every case, so a harness change after R1 would stale every record. A0 builds the routed arm's support, every grader, per-case arm files that replace the shared ones, and the shared shell parser's move into `wslib/`, with every command form the new guards must see.
- **Sub-batch A merges as one, with R1's records.** The machinery page's trap allows no pull request until the commit holding the eval records passes every hook, and `eval_record` fails every case once the harness changes. So A0 to A4 share one branch and one pull request. C1, C2 and C7 need none of A's code and start from main at once.
- **Recordings and their cost.** R1 after the harness and structure changes; R2 at close, with the routed arm in a separate session. Proof attempts for the adversarial-review and debugging playbooks, each starting with a bare-only baseline, at 22 runs per case so one lost run cannot sink the gate, with the baseline and the recording in separate sessions. Expected total: 619 agent runs on the small model, or 754 if R1 needs its one retry, plus about 150 short selection runs, at most 150 per session. A margin re-record adds 45 runs. The 800-run stop leaves room for all three re-records without the R1 retry, and for one with it.
- **R1 also tests M2's open question, but cannot settle it alone.** The guided arm slipped from 45 to 40 of 45 after M2's index grew, and 17 runs went looking for `docs/rules/`. R1 gives each case's guided arm the rule pages its code paths match. It changes the contract and index in the same recording, so the result is confounded, and the report says so.
- **Wrappers only for what can run now.** Each core procedure that can run today gets a skill wrapper. Lane drafts, and the core pages that need M4's review machinery or M8's providers, get none yet: a wrapper's description loads into every session and would route agents to a procedure that cannot run. The wrapper check lists the waiting pages by name.
- **The always-loaded layer gets measured ceilings.** The contract and tool pointers stay under 6,000 bytes (3,646 today), and the wrappers' descriptions under 9,000 bytes in all. These are ceilings, not targets. The routed arm's result sets the final budget, recorded in `m3.md`.
- **The shell guards get the facts they decide on.** Today the before-shell event carries only the command. An amendment to decision record 0004 adds the working copy, the session, the lease holder and the target repository, before any guard that needs them.
- **The outward-write guard refuses every write on other repositories.** Agents here may publish and merge their own pull requests after CI passes. The new guard refuses approval everywhere. On a repository not in the instance's own list it refuses every write command: creating, commenting, reviewing, publishing, merging, and `gh api` calls that write. Only this repository is listed, and an adopted instance starts with an empty list. Agents cannot edit the list; a person edits it from a terminal.
- **One plan, approved once, in three sub-batches.** The program asked for one plan per sub-batch; one plan with three sub-batches keeps a single red team and a single approval. Any change after approval is a dated entry under "Changes after approval", approved one by one as template rule 6 says. Edits to hashed files that wait for slice Z are not changes of plan: they go in a list under "Results".
- **Builders read the private port catalog, never the work workspace.** The catalog was written behind the wall and holds generic descriptions only. B0 builds a private ledger that maps every catalog item to a page or a reason, and orders one walled-reader pass for the entries too thin to build from, before any page is written.

## Goal

Everything a person or agent reads in order to work here exists, written fresh, and each procedure says whether it is proven. The safety machinery M2 did not build is in place, with cases and CI on three systems. A new instance can adopt the kit, and a drift check catches a hand edit to a file the kit owns.

## Non-goals

- No trap tables for one tracker or one git host, and no provider adapters. Those are M8.
- None of the six procedures and six pieces of machinery the catalog leaves out, and nothing the maintainer's own records retired: the prompt-nudge hook, the unattended loop harness, stored knowledge-graph output, the kit health check, prompt wrappers for a second tool, and code-map freshness as a blocking gate.
- No environment slots, code maps, architecture model, machine-state records, review machinery, or page on verifying a change in a local environment. Slots, code maps and that page come with the Umbraco instance in M5; machine-state records come in M4 or M5; review machinery is M4. The maintainer agreed to both deferrals on 2026-11-17.
- No request door and no release-and-rollback draft. The catalog has no source for either; M9 and M11 build them from real work.
- No edit to a file the eval hashes, except in sub-batch A and the closing slice. The list is whatever `covered_files` in `parts/eval_record.py` returns for each case. Today that is `AGENTS.md`, `CLAUDE.md`, `INDEX.md`, `docs/playbooks/fix-a-bug.md`, `docs/definition-of-done.md`, `parts/no_stage_all.py`, `evals/arms.json`, `evals/two-line.md`, the harness, the cases, their acceptance tests and their scaffolds. A0 adds the rule pages and the shared shell parser. One exemption: B7 may add and edit files that are hashed only into a case B7 adds. A slice that needs any other such edit queues it for the closing slice, in the list under "Results".
- No third-party packages in the engine, the parts or the tests CI runs.
- No outward writes beyond this repository: no upstream repository, no issue, no comment.
- No page copied or paraphrased line by line from the work workspace, and no re-sync with it after this milestone.
- No instance repository. The kit is proven on a scratch instance; the first real one is M5.
- No wrapper for a lane draft, or for a core page that cannot run before M4 or M8.

## Why this needs a plan

It fails two size-gate conditions: it is far more than one screen of diff, and far more than a day of work. Several slices change gates, and a broken hook can lock a session out.

## Slices

Every slice is built in its own worktree under `.claude/worktrees/`, on a branch `m3/<slice>`, except sub-batch A, whose five slices share the branch `m3/a` and one worktree. A slice that touches a machinery path merges through a pull request; a doc-only slice may push straight to main from its worktree, as [changing the machinery](../changing-the-machinery.md) allows. The tier comes from the [orchestration rules](../orchestration.md): every slice that changes a gate, a hook, a grader, CI or the contract, and every review, runs at the driver tier.
