# Instruction review: docs/decisions/0005-concurrent-sessions-and-the-edit-ledger.md

Read beside it: `AGENTS.md`, `INDEX.md`, the uncommitted changes to `README.md` and `docs/parts.md`, `docs/decisions/0004-the-hook-contract.md` with its uncommitted change (its "Shell events" and "The rules the shell guards share"), and from commit 35e641c `wslib/gitrules.py` (`read`, `unresolved`, `config_write`), `wslib/shell.py` (`CONFIG_ENV`, the alias loop), `wslib/shellfacts.py` (`aliases`), `parts/no_discard.py`, `parts/push_lease.py` and their cases files. ## Findings

| # | Class | Where | Finding | Disposition |
|---|---|---|---|---|
| 1 | contradiction | The discard guard, "Aliases and config writes" | The bullet says a `GIT_CONFIG_*` variable set on a form the guard decides on is refused "from any working copy". Only `GIT_CONFIG_GLOBAL`, `GIT_CONFIG_SYSTEM` and `GIT_CONFIG_NOSYSTEM` count, plus an include or an unreadable key, as decision 0004's "Config writes" bullet says; `GIT_CONFIG_COUNT` or `GIT_CONFIG_PARAMETERS` setting an ordinary key passes. The refusal also reaches another repository, which the bullet's "working copy" does not cover and where the guard otherwise passes every form. Verified: in a linked worktree `no_discard.decide` passes `GIT_CONFIG_COUNT=1 GIT_CONFIG_KEY_0=user.name GIT_CONFIG_VALUE_0=x git reset --hard` and the `GIT_CONFIG_PARAMETERS` form, and refuses the `HOME` and `XDG_CONFIG_HOME` forms; it refuses `HOME=/tmp git -C /other reset --hard` and passes `git -C /other reset --hard` where `/other` is kind `other`. | fixed: the bullet names `HOME`, `XDG_CONFIG_HOME` and the three `GIT_CONFIG_GLOBAL`, `SYSTEM` and `NOSYSTEM` variables, and an include or unreadable key by `-c`, `--config-env` or `GIT_CONFIG_*`, refused wherever the call acts. |
| 2 | contradiction | The push guard | The paragraph says a push from a linked worktree passes, and so does a push in another repository, then that a push with "`HOME`, a `GIT_CONFIG_*` variable or an include set on it" is refused. It does not say that refusal holds from a linked worktree and another repository too, so the sentences read as conflicting, and it leaves out `XDG_CONFIG_HOME`, which is refused. Verified: `push_lease.decide` refuses `HOME=/tmp git push` and `XDG_CONFIG_HOME=/tmp git push` from a linked worktree and `HOME=/tmp git -C /other push` in another repository, and passes plain `git push` from the linked worktree and the `GIT_CONFIG_COUNT` form setting `user.name`. | fixed: the paragraph points to that list and says the refusal holds from a linked worktree and from another repository too. |
