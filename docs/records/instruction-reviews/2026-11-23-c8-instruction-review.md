# Instruction review: docs/playbooks/instruction-review.md

This records the review of C8's edit to the instruction review playbook, its new skip reason included, for its author and its readers.

**In short:** 3 findings, none blocking: 2 enforcement, 1 placement. The new reason works as the page says for an instance's first commit and an upgrade, but "checked, not taken on trust" overstates it: a commit that deletes a page the lock never held passes, and so does one that edits a seeded page and rewrites its hash in the lock.

## Scope

In scope, from `git diff 3c15e23 -- docs/playbooks/instruction-review.md`: under "When it runs", the added clause naming the two seed pages under `kit/seed/`; the reasons table's new row `as the kit wrote it`; the sentence that now says "For the first three reasons the check reads the reason, not the change"; and, under "Rules", the edited skip-reason row and the new row for `as the kit wrote it`. The rest of the page was read for context only.

Read beside it: `AGENTS.md`, `INDEX.md`, `README.md`, `workspace.json` (the `review_trailer` and `direct_push` entries), `docs/decisions/0007-the-kit.md`, `docs/procedure-endings.md`, `kit/seed/README.md`, `parts/review_trailer.py`, `parts/review_trailer.cases.json`, `wslib/kitlock.py`, and `tests/test_kit.py`.

Run, in the worktree: `python3 ws.py selftest` (review_trailer 23 of 23 cases, every part ok). `python3 -m unittest tests.test_kit -b` fails 9 of 27 tests in the worktree, because `adopt` reads only tracked files and `docs/decisions/0007-the-kit.md` is untracked, so the instance's links check fails. In a scratch clone with the whole C8 change committed, all 27 pass, `test_the_first_commit_passes_the_hooks_as_the_kit_wrote_it` included.

Run, in a scratch instance adopted from that clone, with `core.hooksPath=.githooks`: the first commit with no trailer is refused "with no instruction review"; with `Instructions-review: skipped: as the kit wrote it` it passes. In the scratch kit, which has no lock, the same reason is refused: "the commit holds no readable kit.lock.json". After `ws.py upgrade` from a newer scratch kit that changed `docs/browsers.md`, the upgrade commit with the reason passes. A new page of the instance's own, `docs/team-notes.md`, committed with the reason, is refused: "not as kit.lock.json holds it". The two experiments behind findings 1 and 2 are in their rows.

## Findings

| # | Class | Where | Finding | Disposition |
|---|---|---|---|---|
| 1 | enforcement | The reasons table, row `as the kit wrote it`; "Rules", the row for that reason | Not blocking. The row says the reason "is checked, not taken on trust", and the rule says it passes "only when every guidance page the commit changes is as the instance's lock holds it". A deleted page the lock never held slips through. In the scratch instance, after the first commit, an ordinary commit added `docs/team-notes.md` (skip reason `front matter only`). The next commit deleted it with `Instructions-review: skipped: as the kit wrote it`. The commit hook passed it, and the commit was made (verified, running). The code passes a deleted page whose lock entry is absent or of another class than synced, seeded or kept (`_as_the_kit_wrote_it` in `parts/review_trailer.py`; verified, reading). That commit was neither the first nor an upgrade. For deletions, the reason is the author's word, as the first three are. No case covers a deleted page the lock never held (verified, reading the cases). Either the check should refuse a deleted page the lock never held, or the page should name this as an exception. | fixed: the row says the check compares each page the commit leaves in place and refuses the deletion of a page the lock still holds; it no longer says the reason is checked, not taken on trust. |
| 2 | enforcement | The reasons table, row `as the kit wrote it` | Not blocking. "Checked, not taken on trust" holds only while the lock in the same commit is honest. In the scratch instance, one commit appended a line to `AGENTS.md`, which is seeded, and wrote that file's new hash into `kit.lock.json`. With `Instructions-review: skipped: as the kit wrote it`, the commit hook passed it, and the commit was made (verified, running). `kit_drift` does not compare seeded files, so no other check catches it (verified, reading decision 0007's "Drift" paragraph and its classes table). Decision 0007 lists the editable lock under "What it gave up". It says a lock change reaches main only through a pull request, where it shows in the diff. `kit.lock.json` is on `direct_push`'s `machinery` list (verified, reading `workspace.json`). The page names neither that limit nor where the trust moves. A reader takes the skip as verified by machine when it rests on the lock's diff being read in review (inferred). | fixed: the row says the check trusts the lock in the same commit, and that the lock is machinery, so its change shows in a pull request's diff. |
| 3 | placement | "When it runs", the added clause on the two seed pages under `kit/seed/` | Not blocking. The playbook is synced: every instance gets it (verified, `docs/playbooks/instruction-review.md` has class `synced` in the scratch instance's lock). The added clause describes the kit's own repository. An instance has no `kit/` folder (verified, listing the scratch instance), yet its seeded `workspace.json` still lists `kit/seed/README.md` and `kit/seed/evals-README.md` under `guidance` (verified, reading it). An instance's reader is told that two non-existent paths are guidance pages and "become an instance's README and eval page". That clause belongs in the kit-only material, such as decision 0007, or should be worded so it holds in both places. The older clause on `plugin/` has the same shape and is outside this change. | fixed: the clause now says the seed pages are on the list in the kit's own repository. |
