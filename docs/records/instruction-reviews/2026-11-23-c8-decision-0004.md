## Findings

| # | Class | Where | Finding | Disposition |
|---|---|---|---|---|
| 1 | enforcement | "The exceptions", the `kit_drift` row, "hashes each synced file's text as `ws.py drift` does, so the check and the command agree" | Not blocking. They hash different inputs. `ws.py drift` hashes the file's bytes (`digest(full.read_bytes())` in `kit.drifted`). The check hashes `snapshot.read(path)`, which decodes with `utf-8-sig` and so drops a byte-order mark. It also returns `None` for a file holding a NUL byte or bytes that are not UTF-8 (verified, reading `wslib/snapshot.py` and `parts/kit_drift.py`). Verified in an instance: with a byte-order mark added to `docs/browsers.md`, `drift` reported "docs/browsers.md: edited since kit 0.3.0", and `check` gave no `kit_drift` finding. Such an edit therefore passes the commit hook and CI's `check`, and fails only CI's `drift` step and a later upgrade. In the other direction, a synced file that is not UTF-8 text would fail the check as "cannot be compared" while `drift` passes it (inferred; no synced file today has a byte-order mark, a NUL byte or bytes that are not UTF-8, verified by a scan of the instance's synced files). | fixed: `kitlock.digest` leaves out a leading byte-order mark, so the check and `ws.py drift` read it alike, with a `kit_drift` case; the row says they hash with one function. |
