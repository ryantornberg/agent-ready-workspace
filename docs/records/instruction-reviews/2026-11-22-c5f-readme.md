# Instruction review: README.md

This records the review of C5f's README edits on the secrets guard and `ws.py with-secrets`, for its author and its readers.

**In short:** 2 findings: 1 contradiction, 1 enforcement. Under Codex's `agent-ready` profile, which the README tells a person how to turn on, `with-secrets` cannot read the secrets file in the main working copy and exits 2, yet the row offers it as the route in both tools. What a fix broke and what the first reading missed:

1. **contradiction, blocking.** "## Limits", the Codex bullet, "a person who uses it names a file outside the workspace in the hook's `"file"`", and the row's "a person first moves the file outside the workspace". `tests/test_secrets.py`'s `test_the_file_is_the_one_the_manifest_names` asserts that the manifest's `"file"` is `.env`. Verified: in the copy, with `"file"` set to agent settings' own example, `~/.config/agent-ready-workspace/secrets.env`, `python3 -m unittest tests.test_secrets -b` fails that test; CI runs the whole suite (`unittest discover` in `.github/workflows/ci.yml`, verified, reading). An agent that sets this up as the page says runs a test suite that fails. The `"file"` also sits in the committed `workspace.json`, so the move applies to every person in the workspace, not only the one who uses Codex, and no page says so (inferred, reading). The fix round created this. Disposition: fixed, the second fix round: the Codex bullet now says to keep the file outside the workspace and name it in `WS_SECRETS_FILE` in a person's own shell, so `workspace.json` stays as it is; the test asserts the default and the variable.
2. **enforcement, not blocking.** The same bullet: an absolute `"file"` is not refused to the shell. With `"file": "/srv/team/keys.env"`, `cat /srv/team/keys.env` passes `decide`, and in the copy `test_the_hook_refuses_reading_the_file_with_secrets_reads` fails (verified). `_patterns` keeps the leading `/`, and `_ends` drops it from every path it compares, so the pattern never matches (verified, reading). The page's `~/` example is refused; no limit names an absolute path, the natural form of "a file outside the workspace". Disposition: fixed, the second fix round: an absolute `"file"` now matches, with cases.
