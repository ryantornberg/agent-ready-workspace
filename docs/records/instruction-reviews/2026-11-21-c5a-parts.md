# Instruction review: docs/parts.md

This records the instruction review of slice C5a's change to the parts page, for its author and for anyone adding an after-edit or stop hook.

**In short:** 5 findings: 4 contradiction, 1 trigger. The page gives the stop gate two different time limits, and leaves unlabelled three cases where the stop gate or its wiring acts otherwise than the page says.

## Scope

In scope: the changed text of `docs/parts.md` (the event table and the paragraph after it, the new rows of the NEEDS table, the wiring paragraph, the edit ledger paragraph, and the `chain_reminder` and `stop_gate` rows of "The parts here"), read against the whole page. Read beside it: `AGENTS.md`, `INDEX.md`, `README.md`, decisions 0004 and 0005 with their C5a amendments, `wslib/parts.py`, `wslib/events.py`, `wslib/runner.py` (`command_after_edit`, `command_stop`, `stop_event`, `index_fact`, `command_ledger`), `wslib/gate.py`, `wslib/ledger.py`, `parts/chain_reminder.py`, `parts/stop_gate.py` and their cases files, `workspace.json`, `.claude/settings.json`, `.codex/hooks.json`, `tests/hook_cases.py`, `tests/hooks/after-edit.json`, `tests/hooks/stop.json` and `tests/test_after_edit_and_stop.py`. Commands run: `python3 ws.py selftest`, `python3 tests/hook_cases.py -k gate`, `python3 -m unittest discover -b tests -p 'test_after_edit_and_stop.py'`, and the stop hook and `ws.py ledger --add` on a scratch copy of the worktree.

## Findings

| # | Class | Where | Finding | Disposition |
|---|---|---|---|---|
| 1 | contradiction | The NEEDS table, the `gate` row; The parts here, the `stop_gate` row | The NEEDS row says the gate's runs get 18 seconds in all. The `stop_gate` row says a run fails when it runs out of 20 seconds, and the hook case runner's budget table calls 20 seconds the stop gate's own limit. The page never says that 18 seconds is the runs' deadline inside the hook's 20. A run is cut off at 18 seconds, not 20. Verified: `gate.SECONDS` printed `18.0` on the scratch copy; read the module docstring of `wslib/gate.py`. `parts/stop_gate.py` repeats the 20 in its docstring and its timed-out message. | fixed: the `gate` row says the runs share 18 seconds so the hook answers within its 20, and the `stop_gate` row names the shared 18 seconds. |
| 2 | contradiction | A hook, the paragraph after the event table; The parts here, the `stop_gate` row | The paragraph says none of the four quiet events ever fails, and on any error the runner prints nothing and exits 0. The `stop_gate` row says it acts only for a session with entries of its own. Yet an edit ledger that cannot be read makes the stop gate refuse the stop, even for a session with no edits at all. The exception is deliberate, since `test_an_unreadable_ledger_refuses_once_without_running_anything` holds it, but the page does not label it. Verified: with a malformed `ws-ledger`, a stop for a session with no entries printed `Refused: stop_gate: the stop gate could not run the check and the tests...` and exited 2 in the workspace's own shape, and printed a `"decision": "block"` reply under `--tool claude-code`. | fixed: the paragraph after the event table labels the exception: an edit ledger that cannot be read makes the stop gate refuse once. The `stop_gate` row names it too. |
| 3 | contradiction | The edit ledger, the paragraph and the command table | The paragraph says the stop gate reads each entry's session, and the table says `ws.py ledger --add` records files "this session wrote another way". An `--add` entry carries no session, so the stop gate does not count it as the session's own. A session that wrote its files through the shell and recorded them this way finishes without the gate. The page does not say so; the README's limits and decision 0005 do. Verified: on the scratch copy, `ws.py ledger --add newfile.txt` wrote the bare line `"newfile.txt"`, `ledger.session_entries` returned `[]`, and a stop for that session exited 0 with no output. | fixed: the `ledger --add` row says its entries carry no session, so the stop gate does not see them. |
| 4 | contradiction | The launcher, "When it fails" | The launcher section has only two kinds of wiring: a guard's, which refuses when no Python will do, and a reminder's, which passes. The `stop_gate` hook refuses and sets no `MODE = "remind"`, but its wiring ends in `|| exit 0`, as the changed wiring paragraph says. So with no usable Python the stop gate is skipped and the session stops unchecked. The launcher section does not name this third case. Verified: read `parts/stop_gate.py` (no `MODE`) and the `Stop` lines in `.claude/settings.json` and `.codex/hooks.json`. Inferred: the skip itself, from the launcher's documented exit 2 and the `|| exit 0`; not run without a Python. | fixed: "When it fails" says the stop gate's wiring passes like a reminder's, and the gate is then skipped. |
| 5 | trigger | `INDEX.md`, Topics | The index routes session-start notices and two kinds of commit refusal to "The parts here", but no row fires for a refused stop, the stop gate, or the reminder shown after an edit. An agent that looks up why its stop was refused finds no topic in the index. The refusal message does name decision 0005, so the agent is not stranded. Verified: no row of `INDEX.md` contains "stop", "after-edit" or "chain reminder" (grep). Inferred: that an agent would search the index rather than follow the message's link. | queued for slice Z: `INDEX.md` is hashed, so a Topics row for the chain reminder and the stop gate joins the list under "Results". |
