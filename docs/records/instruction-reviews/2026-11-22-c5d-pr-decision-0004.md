New defects:

- enforcement, "What a push sends", the `gitrules.earlier_change` bullet: "`push_lease` refuses a worktree's push of HEAD, or a bare one, after one" is false for HEAD's reflog forms. With the lease `other-live`, `push_lease.decide` from the worktree refuses `git switch --ignore-other-worktrees main && git push origin @` and `git checkout --ignore-other-worktrees main && git push origin HEAD`, but passes `git switch --ignore-other-worktrees main && git push origin 'HEAD@{0}:refs/heads/y'` and the same with `'@{0}:refs/heads/y3'` (verified, `decide`). Real git then created `y` and `y3` on the remote at the main copy's unpushed commit (verified). The cause: `_shared` reads a source as HEAD only when it is `HEAD` or `@` or starts with `HEAD~`, `HEAD^`, `@~` or `@^`, and `HEAD@{0}` cuts to `HEAD`, not the main copy's branch (verified, reading `parts/push_lease.py`). The same reading passes `@{-1}`, the branch checked out before: after the worktree had checked out `main`, `git push origin '@{-1}:refs/heads/z'` passed `decide` and sent the holder's commit (verified). Disposition: fixed. `_shared` in `parts/push_lease.py` reads every source that starts with `HEAD` or `@` as HEAD after an earlier change, and `gitrules.push_updates` leaves a push unresolved when a source names a branch checked out earlier (`@{-N}`), or a reflog entry with no destination, so both guards refuse it; `no_force_push` refuses `git push -f origin @{-1}`. Cases in both parts and in `tests/test_force_push.py`. This was the second fix round on the worktree push, the last the stop rule allows.

Author's change after the re-check: CI found a `git push` over its time budget on macOS, so the runner now works out a push's target with three git calls at most, and reads `branch` and `main_branch` from each git folder's `HEAD` file instead of `git worktree list`. The `branch` bullet of "What a push sends" says so; nothing else on the page changed.

Author's change after CI's second timing failure on macOS: `no_force_push` no longer reads the target of a push that names literal refspecs and forces, deletes and prunes nothing, since config can force only a push with no refspec. Such a push passes even from a folder the parser cannot place. The `no_force_push` bullet of "What a push sends" says so; nothing else changed.
