This records the instruction review of the C4 amendments to decision 0005, for its author and for anyone running two sessions at once.

**In short:** 3 findings: 1 contradiction, 1 trigger, 1 enforcement. The push guard does what it says from the main copy, but a worktree can publish the same commits, the merge helper knows only Claude Code's own lease, and the In short line does not mention pushes.

## Findings

| # | Class | Where | Finding | Disposition |
|---|---|---|---|---|
| 1 | enforcement | Decision, The push guard | The guard exists so that no other session publishes the holder's unfinished commits, and it lets every push from a linked worktree pass. Branches live in the shared git folder, so a worktree's `main` is the holder's `main`. `git push origin main` or `git push --all origin` from a worktree publishes the holder's commits, and the guard allows both. Verified: `decide` refused neither on the part's linked-worktree event, and `refs/heads/main` names the same commit from this worktree and from the main copy. | queued for the maintainer: judging what a worktree push sends goes beyond row C4, which guards pushes from the main working copy. The push guard paragraph and the README's Limits now state the gap. |
| 2 | contradiction | Decision, The merge helper and the lease | It says a holder whose process is the caller's own agent tool does not hold the update back. Verified: `_update` in `wslib/merge.py` calls `tool_pid("claude-code")`, which returned None with no `CLAUDE_PID`. The Codex outcome is inferred from that code, not run. | fixed: the paragraph says only the caller's Claude Code process is recognized, and that under Codex any live holder holds the update back. |
| 3 | trigger | In short | The In short line names only the guard against git commands that drop the holder's work. The new guard refuses a push, which drops nothing.
