# Instruction review: docs/decisions/0004-the-hook-contract.md

This records the review of C5f's edits to decision 0004, the secrets guard's row and amendment, for its author and its readers.

**In short:** 5 findings, none blocking: 4 enforcement, 1 contradiction. A redirection inside `bash -lc` passes the guard. A nested `with-secrets` runs git unseen. A `.cmd` child runs under a shell on Windows. The `wslib.secrets` row admits a module that reads the secrets file and starts processes. The In short line says no command names a secrets file, though `ls .env` passes by design.

What a fix broke and what the first reading missed:

1. **enforcement, not blocking.** The C5f amendment, "a shell's `-c` text, `-lc` and `-c -e` included". The new rule takes the first word after the `-c` group that does not start with `-` or `+`, so an option's value is taken as the text: `bash -c -o pipefail 'cat < .env'` passes `decide`, and so does the `-O extglob` form (verified). bash runs the last word as the command: in a temporary folder with a fake `.env`, `bash -c -o pipefail 'cat < .env'` printed the file (verified). The line passed before the fix too, so the fix did not break it; neither the README's limits nor agent settings' name it. The form is rare (inferred). Disposition: fixed, the second fix round: the shell's text is the first word after `-c` that is neither an option nor the value of `-o` or `-O`, with cases for `-c -o pipefail` and `-O extglob -c`; the paragraph names the form.
