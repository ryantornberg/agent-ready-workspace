# Instruction review: docs/decisions/0004-the-hook-contract.md

This records the review of C5f's edits to decision 0004, the secrets guard's row and amendment, for its author and its readers.

**In short:** 5 findings, none blocking: 4 enforcement, 1 contradiction. A redirection inside `bash -lc` passes the guard. A nested `with-secrets` runs git unseen. A `.cmd` child runs under a shell on Windows. The `wslib.secrets` row admits a module that reads the secrets file and starts processes. The In short line says no command names a secrets file, though `ls .env` passes by design.

## Findings

| # | Class | Where | Finding | Disposition |
|---|---|---|---|---|
| 1 | enforcement | The dated paragraph "Amended 2026-11-22, M3 slice C5f", "the part reads each `<` and `<>` from the parse, inside substitutions, `sh -c` and `eval` too" | Not blocking. A redirection inside a shell whose `-c` is joined to another flag, or followed by one, is not read. `bash -lc 'cat < .env'`, `bash -ec 'cat < .env'`, `sh -xc 'cat < .env'` and `bash -c -e 'cat < .env'` pass `decide`, and `bash -lc 'cat < .env'` passes the whole hook chain with exit 0, while `bash -c 'cat < .env'` is refused with exit 2 (all verified). `_inner_text` looks for a word that is exactly `-c` and takes the next word as the text, so `-lc` is missed and `-c -e` reads `-e` as the text (verified, reading). The parser itself reads a `-lc` body: `bash -lc 'cat .env'` is refused (verified), so the same file passes after `<` and is refused as an argument. `bash -lc` is a common form for an agent's command (inferred). Neither the README's limits nor agent-settings' "Limits" name this miss (verified, reading). | fixed: the part finds `-c` inside a group of flags and takes the first word after it that is no option, so `bash -lc`, `-ec`, `sh -xc` and `bash -c -e` are read, with cases; the paragraph names them. |
| 2 | enforcement | The same paragraph, "the other shell guards would judge only Python; the part refuses git, gh and any write the parser reports as that program" | Not blocking. A `with-secrets` whose child is another `with-secrets` runs git unseen. `python3 ws.py with-secrets T -- python3 ws.py with-secrets U -- git push --force origin main` passes `decide` and the whole hook chain with exit 0 (verified). `_with_secrets_child` judges only the outer child, `python3`, and `secrets.refusal` refuses neither `python3` nor `git` (verified, calling it), so the inner command would start `git push --force` with no guard seeing it (inferred, reading `run`). The text says "as that program", so it is literally true, but it is the blind spot the paragraph says the part closes. The README's `with-secrets` limit names a child that shows the value, not one that runs git (verified, reading). | fixed: the hook refuses a `with-secrets` whose program is another `with-secrets`, with a case; the paragraph says so. |
| 3 | enforcement | The same paragraph, "starts one program with no shell" | Not blocking. On Windows a batch file runs under a shell whatever Python is passed. Python's subprocess docs, "Security Considerations": batch files "may be launched by the operating system in a system shell regardless of the arguments passed", with arguments "parsed according to shell rules, but without any escaping added by Python" (verified, reading the docs). `resolve` finds the child through `shutil.which`, so on Windows `npm`, agent-settings' own example, resolves to `npm.cmd` (inferred; not run on Windows). `python3 ws.py with-secrets T -- npm 'x&set'` passes `decide` (verified); that cmd.exe would then run `set` and print `T` is inferred. CI runs on Windows, and no page names this limit (verified, reading the README and agent-settings). | fixed: on Windows `with-secrets` refuses a batch file whose arguments hold a character cmd.exe reads, in `wslib/secretrules.py` with a test; the paragraph and agent settings say so. Whether cmd.exe ran `set` was not run on Windows, so that part stays inferred. |
| 4 | enforcement | "The exceptions", the `secrets_shell` row, "`wslib.secrets`: the programs `python3 ws.py with-secrets` refuses to start" | Not blocking. The row admits the whole module, and the module reads the secrets file and starts processes: `run`, `file_of`, and the modules `os`, `subprocess`, `pathlib` and `shutil` as its attributes (verified, calling `hasattr`). The access test checks only the import's name. Its `reaches` returns only `{'wslib.secrets'}` for source that calls `secrets.subprocess.run`, reads `secrets.os.environ` and calls `secrets.pathlib.Path(...).read_text()`, so with this row a later edit of the part that does any of those passes (verified, calling `AccessContractTests.reaches`). The **In short** line says "a test fails on any other" reach. The M2 red team's finding, which the page's "Amended 2026-11-17" sentence records, was this kind of way past: the engine's own git module. `wslib.gitrules` also imports `os`, so the gap is not new in kind (verified, reading); what is new is a module whose job is reading the secrets file. | fixed: the program list moved to `wslib/secretrules.py`, which imports only `re`, reads no file and starts no process; the part imports it instead of `wslib.secrets`, and the row names it. |
| 5 | contradiction | **In short**, "An agent's shell command dumps no environment and names no secrets file, with the misses the README names" | Not blocking. A command may name a secrets file by design when its program only looks at the name: `ls .env`, `test -f .env`, `git status .env`, `git check-ignore .env` and `git ls-files .env` pass `decide` (verified). The README's new rules row and the `secrets_shell` row in `docs/parts.md` state that exception, and the README's limits, which the line points to, do not list it, since it is not a miss (verified, reading). A reader of the line alone avoids commands the guard allows, the safe direction. The line also names no page for the rule: the part's `PAGE` and both rows point to agent-settings' "Secrets in the shell", which the line does not mention (verified, reading). | fixed: the In short line says the shell runs none of the dumps the guard names and reads no secrets file, links agent settings' section, and points to the README for the misses. |
