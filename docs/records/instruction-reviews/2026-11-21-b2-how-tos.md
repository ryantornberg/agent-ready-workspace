# Instruction review: docs/how-tos.md

This records the instruction review of the new how-to index, for its author and for anyone routing a task through it.

**In short:** 4 findings: 1 contradiction, 2 trigger, 1 placement. The planning row skips the spec gate, the records README has no row or route, the playbook catalog's "per row" proof cell breaks the column's stated rule, and the ways to follow a playbook sit on the wrong page.

## Scope

In scope: the whole page, which is new. Read beside it: `AGENTS.md`, `CLAUDE.md`, `INDEX.md`, `docs/definition-of-done.md`, `docs/orchestration.md`, `docs/layout.md`, `docs/glossary.md` with its diff, and every page a row routes to: `docs/research-ladder.md`, `docs/size-the-work.md` (the gate, the feature ladder and the spec process), `docs/playbooks/README.md`, `docs/templates/hand-off-plan.md`, `docs/safe-refactor.md`, `docs/browsers.md`, `docs/commits.md`, `docs/question-log.md`, `docs/templates/milestone-record.md`, `docs/parts.md`, `docs/changing-the-machinery.md`, `docs/agent-settings.md` and `docs/decisions/0006-what-proven-means.md`. Also read the README's proof table with its diff and `docs/records/README.md` with its diff.

Each row's task and Remember cell was checked against the page it routes to, and each Proof cell against that page's front matter or section proof line. Listed the `kind:` of every page under `docs/` to find how-to and reference pages with no row. Ran `python3 ws.py check`, whose link check resolves every anchor the page uses, and `python3 ws.py rules`.

## Findings

| # | Class | Where | Finding | Disposition |
|---|---|---|---|---|
| 1 | trigger | Planning, the row "Write a plan for work too big for fix a bug" | The row sends anyone writing a plan straight to the hand-off plan template, with no condition. Its Remember cell names only the red team and the approval. The spec process says every piece of work that climbs the ladder gets a spec, and "No plan is written on a spec the person has not agreed to". The template never mentions a spec, and its step 3 says to fill every section at once. So an agent entering at this row writes the whole plan before the spec gate. Verified: read the row, the spec process's "When to write a spec" table and gate, and `grep -i spec` on the template, which found nothing. | fixed: the row now fires on work that climbs the ladder and its Remember cell puts the goal, non-goals and success criteria first, agreed as the spec process says, before the rest of the plan. |
| 2 | trigger | Rules, the first row; the five stage tables | The rule says every how-to and reference page a reader goes to for a task has a row. `docs/records/README.md` is a reference page whose purpose names a task, "for anyone checking what a review or a run found", and has no row. No page links to it either, so it has no route at all. Verified: the `kind:` listing of `docs/`, and a grep for links to `records/README.md` and `](records` across the Markdown, which found none outside the records folder. | fixed: a Finishing row now routes to docs/records/README.md for finding what a past review or run found. |
| 3 | contradiction | How to read the tables; Starting a task, the playbook catalog row | The page says the Proof column copies each page's front matter, and that a reference page carries no proof state; the other reference rows read `reference`. The playbook catalog is a reference page, yet its Proof cell reads `per row`. The exception is not labelled. Verified: read the catalog's front matter, `kind: reference`, and the column's rule. | fixed: the catalog row's Proof cell now reads reference, with each playbook's state in its row there. |
| 4 | placement | Three ways to follow a playbook | The page's purpose is a task, where to go for it and one thing to remember. This section is about starting a playbook, which the page's own rule leaves to the playbook catalog. It also repeats the catalog's wrapper status: none exist yet, slice B6 of M3 adds them, only for procedures that can run today. When B6 lands, both pages must change. Verified: read this section and the catalog's "The page is canonical", which states the same status and links here. That the two will drift is inferred. | fixed: the three ways moved to the playbook catalog, merged with its wrapper status so it is stated once, and this page keeps a one-line pointer. |
