# Instruction review: docs/decisions/0005-concurrent-sessions-and-the-edit-ledger.md

- finding 1: holds for the forms the record names. `git push origin 'main@{0}:refs/heads/x'`, `refs/heads/main@{0}:refs/heads/x` and `main~0:refs/heads/x` are refused, and so are `git switch --ignore-other-worktrees main && git push` and `&& git push origin` (verified, `decide`, the cases and the real-git test). A push of HEAD written as a reflog form after a switch still passes; see the new defect.
- finding 2: holds. The paragraph says a branch made from the main copy's HEAD holds the holder's commits, and that a commit named by its id passes; `push_lease`'s refusal in the main copy gives `git worktree add --no-track -b BRANCH .claude/worktrees/NAME origin/main`, which real git runs and which leaves the new branch at `origin/main` with no upstream (verified). The `lease` and `no_discard` refusals, which send most sessions to a worktree, still give `git worktree add .claude/worktrees/NAME -b BRANCH`, from HEAD (verified, reading `parts/lease.py` and `parts/no_discard.py`), so that route is labelled on this page, not closed (inferred).

New defects:

- enforcement, "What a worktree's push sends": "A push of HEAD, or a bare push, after a call earlier in the same line that can change the branch, such as `git switch --ignore-other-worktrees main`, is refused" is false for HEAD's reflog forms. With the lease `other-live`, `push_lease.decide` from the worktree refuses `git switch --ignore-other-worktrees main && git push origin @` and `git checkout --ignore-other-worktrees main && git push origin HEAD`, but passes `git switch --ignore-other-worktrees main && git push origin 'HEAD@{0}:refs/heads/y'` and the same with `'@{0}:refs/heads/y3'` (verified, `decide`). Real git then created `y` and `y3` on the remote at the main copy's unpushed commit (verified). The cause: `_shared` reads a source as HEAD only when it is `HEAD` or `@` or starts with `HEAD~`, `HEAD^`, `@~` or `@^`, and `HEAD@{0}` cuts to `HEAD`, not the main copy's branch (verified, reading `parts/push_lease.py`). The same reading passes `@{-1}`, the branch checked out before: after the worktree had checked out `main`, `git push origin '@{-1}:refs/heads/z'` passed `decide` and sent the holder's commit (verified). Disposition: fixed. `_shared` in `parts/push_lease.py` reads every source that starts with `HEAD` or `@` as HEAD after an earlier change, and `gitrules.push_updates` leaves a push unresolved when a source names a branch checked out earlier (`@{-N}`), or a reflog entry with no destination, so both guards refuse it; `no_force_push` refuses `git push -f origin @{-1}`. Cases in both parts and in `tests/test_force_push.py`. This was the second fix round on the worktree push, the last the stop rule allows.
