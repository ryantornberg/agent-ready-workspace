# Instruction review: docs/decisions/0005-concurrent-sessions-and-the-edit-ledger.md

This records the review of slice C5d's change to decision 0005, for its author and its readers.

**In short:** 2 findings: 2 contradiction. A worktree's push of the main copy's branch passes when an earlier call in the line switches to it, or when it names the branch as `main@{0}`. And the paragraph's list of what still passes leaves out the commonest way to publish the holder's commits: the worktree's own branch, made from the main copy's HEAD as the refusal advises.

## Findings

| # | Class | Where | Finding | Disposition |
|---|---|---|---|---|
| 1 | contradiction | "What a worktree's push sends", and the **In short** line | The page says `push_lease` refuses a push from a linked worktree "that sends the branch the main working copy has checked out". Two forms that send it pass. `git switch --ignore-other-worktrees main && git push`: the target is worked out before the switch runs, and `push_lease` does not call `gitrules.earlier_change`, which decision 0004 provides for this. `git push origin 'main@{0}:refs/heads/x'`: the branch name is compared after cutting at `~` or `^` only. Verified: with engine facts from a throwaway repository, `decide` passes both, while it refuses `git push origin main`; real git then pushes `main -> main` for the first and creates `x` at main's tip for the second. | fixed: `main@{0}` and other reflog forms are read as the branch, and a push of HEAD or a bare push after a `switch` or `checkout` earlier in the line is refused, with cases and a real-git test; the paragraph says so. |
| 2 | contradiction | "What a worktree's push sends", its last two sentences, against "The push guard" | "The push guard" exists because a push can publish the holder's unpushed commits. This paragraph says a push of the worktree's own branch passes, and lists only "another branch the holder made, or a tag" as what still gets through. A worktree made from the main copy with the command the refusal gives, `git worktree add .claude/worktrees/NAME -b BRANCH`, starts at the main copy's HEAD, so its own branch holds the holder's unpushed commits, and `git push -u origin HEAD` publishes them. Verified: in a throwaway repository, a worktree added that way holds the main copy's unpushed commit, `decide` passes `git push -u origin HEAD` on engine facts, and the remote branch then holds that commit. Inferred: an agent runs the advised command from the main copy's top folder, since the path it gives is relative to it. | fixed: the paragraph says a branch made from the main copy's HEAD holds the holder's commits, and the guard's refusal in the main copy now says to start a worktree from `origin/main` with `--no-track`; a commit named by its id is stated as passing. |
