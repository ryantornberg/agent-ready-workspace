# Instruction review: docs/procedure-endings.md

This records the instruction review of slice B2t's change to procedure endings, for the change's author. The change adds one rule from the maintainer's answer to Q42: off main, a procedure pushes nothing for pages.

**In short:** 8 findings: 4 contradiction, 3 step, 1 trigger; 1 blocking. The `git log origin/main..HEAD` test stops the harmful case it was written for: a fix's branch with code commits is off main. But in the main working copy on a branch other than main, a branch the test calls not off main is sent to `git push origin main`, which is rejected or pushes nothing. The test also calls some branches that hold only pages off main, and commits left on a branch reach its pull request only if someone pushes the branch again, which no step says to do.

## Scope

In scope: the changed text (the **In short** line, the clause in "Where the commit goes", the new push-table row, the "Off main" subsection and the new Rules row), and anything on the page or a linked page that the change contradicts or leaves stale. Read beside it: `AGENTS.md`, `docs/playbooks/instruction-review.md`, `docs/changing-the-machinery.md`, `docs/definition-of-done.md`, `docs/decisions/0005-concurrent-sessions-and-the-edit-ledger.md`, `docs/playbooks/fix-a-bug.md`, `docs/playbooks/git-host-operations.md`, the B2t changes to the tracker operations, search every source, escape analysis, architecture review and review orchestrator playbooks (`git diff HEAD`), `docs/review-in-a-worktree.md`, the Q42 entry under the M3 plan's "Changes after approval", the `direct_push` machinery list in `workspace.json`, and `.github/workflows/ci.yml`. Ran `python3 ws.py check`: exit 0, with only the known warning on fix a bug's eval record. Ran `python3 ws.py rules`: the new row is listed, tagged `prose`.

Ran a scratch experiment in a temporary folder, with a local bare repository as the remote. It ran the page's test, `git log --format='%h %s' origin/main..HEAD`, after `git fetch origin`, in these cases. Verified, each:

- A. A worktree made from `origin/main` with `--no-track`, as the lease refusal says, holding one page commit: the test lists only that commit, so it is not off main, and `git push origin HEAD:main` succeeds. Correct.
- B. A fix's branch with a code commit under `src/` and a page commit: the test lists both, so it is off main. Correct. - C2, C3, D, E and F: see findings 1, 2, 3 and 5.

This worktree's own branch, `m3/b2t`, holds pages only and has no pull request (`gh pr list --head m3/b2t --state all` printed `[]`). The test here lists four commits, made by earlier B2t sessions, one of them a merge of `origin/main`. Verified.

Broke:

- Not blocking. The sentence above the push table says that off main "the table's first row applies and no other". A machinery change and a change to code under `src/` always sit on a branch other than `main`, so that sentence makes the machinery row and the code row unreachable. Read literally, a procedure with a machinery or code commit pushes nothing and opens no draft pull request, against those rows and changing the machinery's step 5. Extend the workspace's and adopt the workspace's step 8 also say who pushes their branch "follows that table's row for machinery", which the sentence now excludes. Verified, by reading. Not blocking, because no command fails and nothing reaches main. The pages that make such commits push their branch by their own step (fix a bug's step 5, changing the machinery's step 5) or by a labelled exception (extend's and adopt's step 8), and anything left unpushed is named in the report (inferred). Scoping the sentence to pages, as the subsection's first line is, settles it.
- Not blocking. The main-copy row says "as the next section says", linked to `#when-main-has-moved`. The next section is now "Off main", not "When main has moved". The link goes to the right place; the words point at the wrong one. Verified, the page's headings.

Missed:

- Not blocking. The fix record template says to commit the record on the fix's branch and, after the push, "commit and push the record once more on that branch", as the order of procedure endings. The new rule says push nothing off main, and the template does not label an exception. Following procedure endings, the record's last commit never reaches the pull request; following the template, the branch is pushed, which carries nothing to main. Verified, by reading `docs/templates/fix-record.md` "Committing it"; the effect is inferred.
- Not blocking. In a worktree made for pages, the test lists a merge of `origin/main` into the branch, which is neither a page commit nor a code commit. Verified twice: in the experiment, and in this worktree, where `git log --format='%h %s' origin/main..HEAD` lists `c43da8d Merge remote-tracking branch 'origin/main' into m3/b2t` and `git merge-base --is-ancestor origin/main HEAD` exits 0, so no `git pull --rebase` removes it before the push. The page does not say whether such a merge counts as accounted for. An agent that counts it as unaccounted for calls a pages worktree off main and leaves its pages unpushed. That is the safe direction, and the report names the commits (inferred).
