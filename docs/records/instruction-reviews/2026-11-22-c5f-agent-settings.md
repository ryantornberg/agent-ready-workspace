# Instruction review: docs/agent-settings.md

This records the review of C5f's edits to the agent settings page, on the secrets guard and `ws.py with-secrets`, for its author and its readers.

**In short:** 5 findings: 3 contradiction, 1 enforcement, 1 trigger. Under the page's own Codex profile, `with-secrets` cannot read the secrets file in the main working copy and exits 2. The page tells an agent to `echo "$NAME"` while the hook's message says to ask the person, and its Limits list the same echo as a miss. `ps eww` and interpreters dump the environment past the hook, and `ps eww` shows a `with-secrets` child's values. `$NAME` on the command line is filled in by the calling shell, not left empty. `INDEX.md` routes no topic to this page.

What a fix broke and what the first reading missed:

1. **contradiction, blocking.** "Secrets in the shell", the "Under Codex's `agent-ready` profile" bullet, "sets `"file"` to a path outside the workspace, such as `~/.config/agent-ready-workspace/secrets.env`". `tests/test_secrets.py`'s `test_the_file_is_the_one_the_manifest_names` asserts that the manifest's `"file"` is `.env`. Verified: in the copy, with `"file"` set to that example, `python3 -m unittest tests.test_secrets -b` fails that test; CI runs the whole suite (verified, reading `.github/workflows/ci.yml`). An agent that sets this up as the bullet says runs a test suite that fails. The setting is in the committed `workspace.json`, so it moves the file for every person in the workspace, which the bullet does not say (inferred, reading). The fix round created this. Disposition: fixed, the second fix round: the page tells a person under the profile to keep the file outside the workspace and set `WS_SECRETS_FILE` in their own shell, so `workspace.json` stays as it is; `with-secrets` reads the variable first and says so when it cannot read the file; the hook refuses an agent's command that sets it. The test now asserts the default and the variable, not the manifest's value.
2. **enforcement, not blocking.** "**The file**" bullet, "the hook refuses shell reads of that one too". An absolute `"file"` is not refused: with `"file": "/srv/team/keys.env"`, `cat /srv/team/keys.env` passes `decide`, and in the copy `test_the_hook_refuses_reading_the_file_with_secrets_reads` fails (verified). `_patterns` keeps the leading `/`, and `_ends` drops it from every path, so the pattern never matches (verified, reading). "Limits" does not name it. Disposition: fixed, the second fix round: `_patterns` drops a leading `/` or drive from a pattern, so an absolute `"file"` matches, with cases.
3. **enforcement, not blocking.** The dump bullet, "`ps` with `e` or `-E`". `ps Eww` passes the whole chain with exit 0 (verified); `_ps_environment` looks for a lower-case `e` in a group with no dash and `E` only in a group with one (verified, reading). macOS `ps` reads a first word without a dash as its options, as `ps aux` shows, and its `-E` displays the environment (`man ps`), so `ps Eww` prints it there (inferred; this machine's sandbox showed no environment for any `ps` form, so the output was not seen). The fix round added the rule; "Limits" does not name the form. Disposition: fixed, the second fix round: a letter group holding `E` is refused as one holding `e`, with a case; the dump bullet says so.
4. **enforcement, not blocking; the first reading missed it.** "It refuses some programs", "a program that runs another, such as `sudo`, `xargs` or `nohup`", and the Rules row "refuses ... a program that runs another as its child". `python3 ws.py with-secrets T -- find . -exec printenv T ;` passes the whole chain with exit 0, and `secretrules.refusal` returns `None` for `find`, `npx` and `parallel` (verified). So the command would start `find`, which runs `printenv` with the value (inferred, not run). "Limits" names a program that starts a shell, such as `make`, not one that runs another program directly. Disposition: fixed, the second fix round: `find` and `parallel` join the programs `with-secrets` refuses, and the hook refuses a child line that runs a program through a wrapper or prints the environment, with cases; `npx` joins the limit's examples of a program that starts one itself.
