# Instruction review: docs/decisions/0004-the-hook-contract.md

This records the instruction review of the C5c edits to decision 0004, for its author and for anyone writing a guard on git commands.

**In short:** 7 findings: 5 contradiction, 1 step, 1 trigger. An unresolved `git_config` fact refuses nothing, a `git config` write to a config file passes by its key with no label saying so, and the page names a key list and a push-destination guard that the page does not define and the code does not have.

In scope: the new before-edit bullet under "What a part may read", the `"aliases"` and `"git_config"` rows of the Shell events table, the new sentence closing the `targets` bullets, the new "The rules the shell guards share" section, the four changed or added rows of the exceptions table, and the C5c Amended paragraph, read against the whole record. Read beside it: `AGENTS.md`, `INDEX.md`, the uncommitted changes to `README.md`, `docs/parts.md` and `docs/changing-the-machinery.md`, `docs/decisions/0005-concurrent-sessions-and-the-edit-ledger.md`, and from commit 35e641c `wslib/gitrules.py`, `wslib/shellfacts.py` (`aliases`, `git_config`), `wslib/runner.py` (`shell_event`, `command_hook`), `wslib/parts.py` (`NEEDS`), `wslib/shell.py` (its facts docstring, `GIT_BUILTINS`, `CONFIG_ENV`, `guarded_key`, the alias loop), `parts/git_folder.py`, `parts/git_folder_shell.py`, `parts/no_discard.py`, `parts/push_lease.py` and their cases files. Ran `python3 -m unittest -b tests.test_core.AccessContractTests` (2 tests, OK), `python3 -m unittest discover -b tests -p 'test_git_folder.py'` (16 tests, OK) and `python3 ws.py selftest` (`git_folder` 26, `git_folder_shell` 66, `no_discard` 105 and `push_lease` 31 cases, all ok). ## Findings

| # | Class | Where | Finding | Disposition |
|---|---|---|---|---|
| 1 | contradiction | Shell events, the opening paragraph and the `"git_config"` row | The page says a guard refuses a command whose needed fact is unresolved, and that `unresolved` says why the includes could not be read. Neither holds: `git_folder` and `git_folder_shell` never read `unresolved`, so with the includes unread a write to an included file passes; and `shellfacts.git_config` sets `unresolved` only on a timeout, so a git error leaves it null with the includes missing. Verified: with `git_config` `{"files": ["/h/.gitconfig"], "unresolved": "git did not answer in time"}`, `git_folder_shell` passes `echo x > /h/work.inc` and `git_folder` passes an edit to it; on a throwaway repository whose `.git/config` names an include and then breaks, `git config --get-regexp` exits 128 and `git_config` returns `"unresolved": null` without the include file. | fixed: `git_config` now sets `unresolved` when git exits other than 0 or 1, with a test, and the row labels the exception: the two guards do not refuse while it is set, and the global files are still listed. |
| 2 | contradiction | The rules the shell guards share, "The git folder and git config files" | The bullet says a write to a file in `git_config` is refused when the shell parser reports it, and the parser reports `git config --file` as a write; but a `git config` write to a config file is judged by its key instead, so an ordinary key passes. The exception is not labelled here, though the README states it ("`git config user.email` passes"). Verified: `python3 ws.py hook before-shell` exits 0 on `git config --file ~/.gitconfig user.email x` and on `git config --global user.email x`, and exits 2 on `echo x >> ~/.gitconfig` and `git config --global alias.st status`; `shell_refusals` in `wslib/gitrules.py` skips a `git config --file` write to a config file ("its key decides"). | fixed: the bullet says a `git config` write is judged by its key, whatever file it writes, and that `git config --global user.email` passes. |
| 3 | step | The rules the shell guards share, "Config writes on a call a guard decides on" and "The git folder and git config files" | Both bullets turn on "every key A0's list names", and this page never says which keys those are, so a hook author or a refused agent cannot tell what is guarded without reading code. Verified: the page has no list; the keys live in `guarded_key` in `wslib/shell.py` and the `git_folder_shell` docstring (`remote.*`, `url.*`, `push.*`, `branch.*.pushRemote`, `branch.*.merge`, `remote.pushDefault`, `include.*`, `includeIf.*`, `alias.*`, `core.worktree`, `core.sshCommand`, and a key that cannot be read); `docs/parts.md` gives only examples. | fixed: a new bullet lists the keys and names `guarded_key` in `wslib/shell.py`. |
| 4 | contradiction | The rules the shell guards share, "Config writes on a call a guard decides on" | "A guard that decides by where a push goes also counts every key A0's list names" reads as a rule in force, but no guard decides by where a push goes: no part declares `"targets"`, and no part calls `config_write` with `every_guarded=True`, only a test does. A reader takes `push_lease`, which 0005 calls the push guard, to be one, and it is not. Verified: `grep` of `NEEDS` in `parts/*.py` and of `every_guarded` in the repository; `push_lease.decide` passes `git -c remote.origin.pushurl=x push` from a linked worktree. | fixed: the bullet says the option is for the push-destination guards of slices C5d and C5e, that no guard uses it yet, and that `push_lease` passes the example from a worktree. |
| 5 | contradiction | The rules the shell guards share, "Aliases" | The bullet says an alias read from config is unresolved when the command changes its config with "a `GIT_CONFIG_*` variable", while the next bullet names only `GIT_CONFIG_GLOBAL`, `GIT_CONFIG_SYSTEM` and `GIT_CONFIG_NOSYSTEM`, and the code follows the narrower list. Verified: with an `st = status` alias in the main copy and another live lease holder, `no_discard.decide` passes `GIT_CONFIG_COUNT=1 GIT_CONFIG_KEY_0=user.name GIT_CONFIG_VALUE_0=x git st` and refuses `HOME=/tmp git st`; `CONFIG_ENV` in `wslib/shell.py` holds the five named variables. | fixed: the bullet names the three variables. |
| 6 | contradiction | The rules the shell guards share, "Aliases" | The guard expands an alias "only for a name that is not one of git's own commands, as git does", but git tries an external `git-NAME` program on `PATH` before an alias of that name, so a name with both is judged as the alias while git runs the program. Inferred: from the order in git's `run_argv` (built-in, then the dashed external, then the alias); a run to confirm it was refused by this workspace's own live `no_discard` hook. Verified: `read` and the alias loop in `wslib/shell.py` check only `GIT_BUILTINS`, and `shellfacts.aliases` never looks on `PATH`. | fixed: the bullet says git runs a `git-NAME` program before an alias of that name and the guard does not look for one. |
| 7 | trigger | The In short line, and the index row that routes here | The page now holds the rules on writes to a git folder and to git config files, and it is the `PAGE` that the `git_folder` and `git_folder_shell` refusals name. But the In short line speaks only of what a part may read, and the index row reads "What a hook may read; a path inside a worktree; writing a session hook", so an agent asking whether it may write under `.git` or to `~/.gitconfig` finds no route here. Verified: `INDEX.md`'s topic rows; `PAGE` in `parts/git_folder.py` and `parts/git_folder_shell.py`; a search of `INDEX.md` for "git folder", "config" and "alias" finds only the search-aliases section. | deferred: the In short line waits for the maintainer's answer to Q15, on whether an amendment may edit it; the `INDEX.md` row is queued for slice Z, since the eval hashes the index. |
