# Instruction review: README.md

This records the instruction review of the C4 edits to the README, for its author and for readers setting up a copy on GitHub.

**In short:** 4 findings: 1 contradiction, 1 step, 1 enforcement, 1 placement. The new rows run where they say, but the setup leaves out the branch rule the merge helper needs, and two Limits bullets misstate the helper's outcome and the merge hook's reach.

## Scope

In scope: the new paragraph on GitHub's merge settings, the two new rows of What is checked, and by what, and the edited and new bullets under Limits, read against the whole page. Read beside it: `AGENTS.md`, `INDEX.md`, `workspace.json`, `docs/changing-the-machinery.md`, `docs/decisions/0005-concurrent-sessions-and-the-edit-ledger.md`, `.github/workflows/ci.yml`, `wslib/merge.py`, `wslib/runner.py` (`command_merge`), `parts/no_admin_merge.py`, `parts/push_lease.py` and their cases. Ran `python3 ws.py selftest`, `python3 -m unittest tests.test_merge`, `parse_check_runs` and `parse_required` on made-up answers, the merge hook's `decide` on sample commands, and a read-only `gh api` call for the repository's merge settings.

## Findings

| # | Class | Where | Finding | Disposition |
|---|---|---|---|---|
| 1 | step | Try it, the paragraph on GitHub's merge settings | It says an agent merges with `python3 ws.py merge NUMBER`, but not that the helper needs the base branch's rule to name required checks. With none, it refuses every pull request. Its refusal sends the reader to changing the machinery, which describes this repository's rule but not how to set one, and Use it for your own team names no branch rule either. Verified: `parse_required` refused an empty rule, and no page outside changing the machinery mentions a branch rule or a required check. | fixed: the GitHub step now says main needs a branch rule that requires the CI jobs, since the helper refuses every pull request without one. |
| 2 | placement | Try it, the paragraph on GitHub's merge settings | Setting a copy's merge options on GitHub is a one-time adoption step. It sits in Try it, the local walk-through for a fresh clone, rather than in Use it for your own team, where a reader adopting the workspace looks. Inferred. | fixed: the step moved to Use it for your own team, as step 6. |
| 3 | contradiction | Limits, the `python3 ws.py merge` bullet | It says the helper refuses a commit with more than 100 check runs. The helper treats that as a failed step and exits 2, which changing the machinery defines as "a step failed", not 1, "refused". Verified: `parse_check_runs` raised `MergeError` on 101 runs, and `command_merge` turns `MergeError` into exit 2. | fixed: more than one page of check runs is now a refusal, exit 1, with a test in `tests/test_merge.py`. |
| 4 | enforcement | Limits, the `direct_push` and `no_admin_merge` bullet | The bullet lists what gets past the merge hook: another program such as `curl`, a `gh` alias, a script, or a form the parser does not follow. It leaves out a `gh api` call with a variable anywhere in its path, which the parser reads and the hook lets through. Verified: `decide` allowed `gh api -X PUT repos/o/r/pulls/$N/merge -f merge_method=squash`. The repository's settings, read with `gh api`, still allow merge commits only, so GitHub would refuse that squash. | fixed: `no_admin_merge` now refuses any API write whose path is a variable, with two cases; the Limits bullet also names an interpreter. |
