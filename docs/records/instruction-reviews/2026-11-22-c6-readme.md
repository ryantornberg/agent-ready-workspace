What a fix broke and what the first reading missed:

1. **enforcement, not blocking; the fix created it.** "## Limits", the variable test's bullet, "and a second for each guard whose code reads a variable by name, where it reads it". `git_folder` reads variables by name as `git_folder_shell` does: its `NEEDS` is `("git_config",)`, and the runner makes that fact with `shellfacts.git_config`, which reads `HOME`, `XDG_CONFIG_HOME`, `GIT_CONFIG_GLOBAL` and `GIT_CONFIG_SYSTEM` (verified, reading). It gets no second call: `READERS` holds only `git_folder_shell` and `outward_write`, and `ScanTests` pins it to those two (verified, reading). Its one call edits the repository's `.git/config`, which those variables do not decide. Run through the test's own `check` from a scratch script, the existing case "git_folder: a write of the global git config is refused" goes ahead with exit 0 when `HOME` is removed (verified). That is the change of file the bullet's `GIT_CONFIG_GLOBAL` sentence describes: the case writes the file `HOME` named, and with `HOME` unset the guard protects the account's own home instead (inferred, from `git_config`'s fallback to `os.path.expanduser`). So such a case cannot simply join `READERS`. Either give `git_folder` a second call that reaches those variables, or narrow the sentence to the two guards it covers. Disposition: fixed, the second fix round: the sentence names the two guards and their variables, and says that `git_folder`'s refusal of a write to the file `HOME` or `GIT_CONFIG_GLOBAL` named is not tested, since removing the variable changes which file that is.
2. **contradiction, not blocking; whether the fix or the first reading missed it is not known, since the pre-fix text is not on disk.** "## Limits", the variable test's bullet, "A killed commit check leaves no file of its own, with three exceptions". The third exception is a push check: "A push check killed while it runs a tutorial leaves that tutorial's clone in the temporary folder". Tutorials run only on the push path: `run_tutorial` is called only from `runner.push_tutorials`, for a push to main, and `.githooks/pre-commit` runs `ws.py check --staged` (verified, reading). So a killed commit check has two exceptions, and the push check's clone is a separate limit. Say "a killed check" and keep three, or count two and give the push check its own sentence. Disposition: fixed, the second fix round: two exceptions, and the push check's clone in a sentence of its own.
