# Instruction review: docs/decisions/0004-the-hook-contract.md

## Re-check

A fresh re-check of the author's fixes, step 7 of the playbook, read against the uncommitted record, `AGENTS.md`, `INDEX.md`, the uncommitted `docs/layout.md`, decision 0005, `README.md` (its limits), and `wslib/gitrules.py`, `wslib/shell.py` (`guarded_key`), `parts/git_folder.py`, `parts/git_folder_shell.py`, `parts/no_discard.py` and `parts/push_lease.py`. - finding 1: holds. The In short line limits the alias claim to the discard and push guards, and the 2026-11-22 Amended paragraph labels the limit; `git_folder_shell.decide` passes `git cf remote.origin.url evil` and refuses `git config remote.origin.url evil` (verified). The "Aliases" bullet stays unqualified, as the body of a frozen record must. Q17 sits in the workspace queue outside this repository and was not checked (inferred).
- finding 2: holds. The In short line says a `git config` command is judged by its key; `git_folder_shell.decide` passes `git config --global user.email x` and refuses `git config --global core.sshCommand x` (verified).
- finding 3: holds. The In short line names the keys "The rules the shell guards share" lists, and that list matches the sections and variables `guarded_key` tests (verified).

New defects:

- contradiction, the 2026-11-22 Amended paragraph: "The guards refuse an agent's own write of such an alias, by `git config` or into a config file; one a person stored passes" is false. `git config --file /tmp/a.cfg alias.cf config` passes, as the README's limits say a `--file` naming another file does. `GIT_CONFIG_GLOBAL=/tmp/a.cfg git cf remote.origin.url evil` then passes `git_folder_shell.decide`, and so does `HOME=/tmp/h git cf remote.origin.url evil` after a written `/tmp/h/.gitconfig`; with the lease free or the agent's own, `no_discard` and `push_lease` pass both too (verified, `decide`). The cause: `gitrules.shell_refusals` never calls `config_write`, and `no_discard` refuses an unresolved call only while another live session holds the lease (verified, the code). End to end in this repository the hook exits 2 on the `GIT_CONFIG_GLOBAL` line, but only through `no_discard`, because another live session holds the lease (verified, its refusal text). Disposition, fixed: the Amended paragraph drops the false sentence and says how an agent can store such an alias and when the other two guards refuse the call; Q17's wording was corrected to match.
- contradiction, the In short line: "An agent's write into a git folder or to a git config file is refused, by an edit tool or the shell", and the new "A `git config` command is judged by its key instead", read as though every other git command that writes config is refused. `git remote set-url origin evil` exits 0 from `python3 ws.py hook before-shell` and changes `remote.origin.url`, a key the line says is refused (verified). The body limits the rule to "a shell write the parser reports", and the README's `git_folder_shell` limit labels `git remote add` and `set-url`, `git branch --set-upstream-to` and `gh repo set-default` as not seen; the In short line labels neither. The first clause may predate the fix, since finding 2 quotes it, but the reviewed wording is not on record (inferred). Disposition, fixed: the In short line says the write is refused when an edit tool makes it or the shell parser reports it, and that other git commands that change config, such as `git remote set-url`, are not seen, as the README lists.
