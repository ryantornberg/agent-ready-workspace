| 1 | enforcement | "Amended 2026-11-24, M3 slice Z" paragraph; the `secrets_shell` row of "The exceptions" | Blocking. The page says the parser "reads `ws.py with-secrets NAME ... -- PROGRAM` as a wrapper, so every shell guard judges PROGRAM", and the In short line says a shell command reads no secrets file. `_with_secrets_child` in `wslib/shell.py` looks for a word named `ws.py`, `launch.sh` or `start.py` anywhere in a command's words, not only as the program or Python's script, then takes everything after the next `--` as the command and drops the rest. So `cat .env ws.py with-secrets -- true` is read as `true`, and `secrets_shell` passes it, though `cat` prints `.env`; `rm .git/config ws.py with-secrets -- true` is read as `true`, and `git_folder_shell` passes it, though `rm` removes `.git/config`; `rm outward-repos.json ws.py with-secrets -- true` passes `outward_write`. On d2aa593 the first two were refused. Marked blocking because the record states an enforcement that the slice's own change makes false, and the playbook says to mark blocking when in doubt; an agent following the page itself writes nowhere it may not.
