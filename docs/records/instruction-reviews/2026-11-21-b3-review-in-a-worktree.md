# Instruction review: docs/review-in-a-worktree.md

This records the instruction review of the new how-to for reviewing a pull request in a worktree, for its author and reviewers.

**In short:** 5 findings: 1 contradiction, 3 step, 1 placement. In a workspace with real pins, step 6 can never remove the worktree that step 4 filled. The other-host fetch has no branch name to fetch. The page limits review worktrees to pull requests, yet one section uses them for your own commits.

## Scope

In scope: the whole page. Read beside it: `AGENTS.md`, `CLAUDE.md`, `INDEX.md`, `docs/definition-of-done.md`, `docs/orchestration.md` (with its batch 3 diff), `docs/layout.md`, `docs/glossary.md`, `docs/decisions/0005-concurrent-sessions-and-the-edit-ledger.md`, `docs/changing-the-machinery.md`, `src/README.md`, and the other pages of batch 3, chiefly `docs/playbooks/review-orchestrator.md`, `docs/code-review.md` and `docs/playbooks/feedback-walkthrough.md`. Code read: `wslib/pins.py`, `wslib/runner.py` (`command_pins`, `main`), `parts/no_discard.py` and `parts/no_discard.cases.json`. Commands run: `python3 ws.py --help`; `python3 ws.py rules`; `gh pr view --help` (its JSON fields); in a scratch clone of this repository, `git worktree add --detach .claude/worktrees/review-pr-1 HEAD`, `python3 ws.py --root .claude/worktrees/review-pr-1 pins` (prints "No pinned repositories", exit 0) and `git worktree remove` (exit 0); in a scratch pair of repositories with one submodule, the same three steps (see finding 1); `python3 ws.py check` (no finding names this page).

## Findings

| # | Class | Where | Finding | Disposition |
|---|---|---|---|---|
| 1 | step | Steps, steps 3, 4 and 6 | In a workspace with real pins, step 4 checks the pins out as submodules in the worktree. Step 6's `git worktree remove PATH` then always fails with "working trees containing submodules cannot be moved or removed". `git status --short` lists nothing, so the page's reading ("something edited it") is wrong. The page forbids `--force`, so the worktree is never removed, against its own rule "Remove the review worktree when the review ends". Step 3's "remove it as step 6 says, then add it again" fails the same way on a second review of the same pull request. Verified: in a scratch repository with a submodule and an `origin`, `python3 ws.py --root .claude/worktrees/review-pr-3 pins` printed "src/sub: initialized", then `git worktree remove` exited 128 with that message, and `git status --short` printed nothing. Cause: sample-cannot-exercise-path — the step pass runs each command in a scratch clone of this sample, whose `src/` holds no pins, and the brief is silent on paths only a workspace with real pins reaches. | fixed: step 6 now checks the worktree and its submodules are clean, then uses --force only on git's submodule refusal, and reports when the guard refuses; tested in a scratch repository with a submodule. |
| 2 | step | Steps, step 2, the row "A repository on another host" | The row says to fetch the pull request's source branch with `git fetch origin BRANCH`, but no step produces BRANCH: step 1 asks `gh pr view` only for `headRefOid,baseRefName,state`, not `headRefName`. Step 1 is also a `gh` command, and `gh` reads GitHub hosts, so on another host step 1 gives no head commit for step 2's check either. The reader has no input for this row and no way to proceed. The feedback walk-through says instead that other hosts wait for M8. Verified: read steps 1 and 2; `gh pr view --help` lists `headRefName` as a separate field. That `gh` cannot read a non-GitHub host is inferred. Cause: step-pass-skipped — the step pass asks that each step name its input and where it comes from. | fixed: the other-host row is gone; a pull request on another host now stops at step 1 and waits for M8, as the feedback walk-through says. |
| 3 | contradiction | "Why a worktree, as an exception"; Rules, first row; "A worktree at a commit you already have" | The exception gives "one reason": a review needs the pull request's files. The first rule says a review worktree "is used only to read a pull request". The section "A worktree at a commit you already have" makes review worktrees for commits of your own branch, its tip and its base, which the review orchestrator's steps 3 and 4 call for. The page's own exception and rule cannot both hold beside that section, and the second use is not labelled as an exception to the contract. Verified: read the three places and the orchestrator's steps 3 and 4. Cause: contradiction-pass-skipped — the brief names a page contradicting itself between its steps and its rules table as a known trap. | fixed: the exception and the first rule now cover any one commit a review reads, a pull request's head or a branch's tip and base. |
| 4 | step | "A worktree at a commit you already have" | The section gives a command only "for a commit already in this repository". The review orchestrator's step 4 needs a base worktree "made the same way" for every review, including a pull request in a repository pinned under `src/`. For that case the page gives no command, such as step 3's `git -C src/REPO worktree add` form. "Then follow steps 4 to 6" also sends the reader to step 4's command, which names `review-pr-NUMBER`, not `review-COMMIT`. Verified: read the section, step 3, step 4 and the orchestrator's step 4. Cause: step-pass-skipped — the step pass asks that each step be executable as written for every input the page accepts. | fixed: the commit case is now folded into Steps, with COMMIT and PATH defined, so steps 3 to 6 including the pinned -C form apply to it. |
| 5 | placement | "A worktree at a commit you already have", its last paragraph | The stop condition and the report for the whole procedure ("report the pull request, the head commit reviewed, any pinned repository skipped, and the removal") sit under the heading for your own commits, not under "Steps". A reader following steps 1 to 6 for a pull request ends at step 6 with no report step, and finds the stop line only under a heading that does not apply to them. Verified: read the page's headings and both sections. Cause: page-specific — the brief's step pass already asks each procedure to say when it stops and what the report holds. | fixed: the report is now step 7 under Steps, and every earlier stop ends in it. |
