# Instruction review: docs/decisions/0004-the-hook-contract.md

**In short:** 5 findings: 2 enforcement, 2 contradiction, 1 placement. New defects:

- enforcement, "The outward-write guard", the bullet "On a repository outside the list", "`git send-pack` and `git http-push` ... are judged by the URL they name". `_plumbing` takes the first word not starting with `-` as the URL, so an option whose value is a separate word hides the real one. `git send-pack --receive-pack git-receive-pack git@github.com:them/theirs.git main` passes `decide` and the whole hook chain (verified, exit 0), and so does `--exec` (verified, `decide`). Real git accepts that form: `git send-pack --receive-pack git-receive-pack BARE main` created `main` in the bare repository (verified). That it writes to the unlisted repository over ssh is inferred. Disposition: fixed, the second fix round, as the README record's second new defect says; the bullet says the URL is read past the options that take a value..
- enforcement, the same bullet, "A push with `--recurse-submodules=on-demand` or `only` is refused, since each submodule goes to its own remote". git's abbreviation `git push --recurse=on-demand origin HEAD`, and `git -c submodule.recurse=true push origin HEAD`, pass `decide` and the whole hook chain (verified, exit 0). Real git sent a submodule's unpushed commit to the submodule's own remote for both (verified). `submodule.recurse` is not among the keys `config_write` refuses (verified, `decide`). Disposition: fixed, the second fix round, as the README record's first new defect says; the bullet names the forms and the persistent write `git_folder_shell` refuses..
- enforcement, "Shell events", the `"destinations"` row, "a push whose URLs are known carries them with `unresolved` set when only the branch it sends is unknown ... and `outward_write` judges it by its URLs". For a push in a folder that does not exist when the hook runs, the URLs are not known, yet the fact has that shape. `git clone https://github.com/them/theirs t && git -C t push` gives `{"local": true, "path": "origin"}`, the remote's name read as a local path, with `unresolved` "HEAD is detached and the push names no refspec", and `outward_write.decide` passes it (verified, `shell_event` and `decide`). After a real clone that push goes to the cloned URL, `origin` (inferred from git's clone; not run against GitHub). The whole hook chain refuses it only through `no_force_push`, which cannot tell what a push with no refspec sends (verified, `ws.py hook before-shell`); with a refspec, `outward_write` refuses it itself (verified). So the row's condition does not hold, and the guard's own answer rests on another part this page does not name for it. Disposition: fixed, the second fix round. A push target is unresolved, with no URLs, in a folder that does not exist yet and for a word that names no remote and is no path or URL, in `wslib/shellfacts.py` for both facts, with real-git tests; the `"destinations"` row says so, and the "What it cannot judge" bullet names the exception..
