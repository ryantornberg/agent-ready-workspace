# Instruction review: docs/lifecycle-map.md

This records the instruction review of the new lifecycle map, for its author and for critics.

**In short:** 10 findings: 6 contradiction, 2 trigger, 1 placement, 1 eval-case, none blocking. Nine playbooks and how-tos have no row, several State and Planned cells disagree with the pages they link, and the page's update rule lives where no procedure loads it.

## Scope

In scope: the whole page, which is new. Read beside it: `AGENTS.md`, `INDEX.md`, `README.md`, `docs/layout.md`, `docs/authoring.md`, `docs/extend-the-workspace.md`, `docs/how-tos.md` with its uncommitted row, `docs/maintain-the-workspace.md`, decision 0006, `docs/code-review.md`, the pull request template, `evals/arms.json` and the list of `evals/cases/`. Every page the map links was opened, and its front matter and opening read. Ran `git diff --cached`, a script that prints each linked page's `kind`, `proof` and `prove-by`, a script that lists each playbook and how-to under `docs/` with no link on the map, greps for each Planned item's source, and `python3 ws.py check`, which reported nothing on this page.

Outside the findings, each State cell not named below matches its pages' `prove-by`: Request M9, Sizing M9, Design M4 and M9, Build M4 and M6 with fix a bug proven, Local environment M6 and M11, Test M4, M6 and M10, Review M6, Pull request M8, Deploy M11, Learn M6 and M10, Schema M9, Unattended work M4 and M10, Keeping the guidance true M4, M5 and M10 (verified, front matter). The **In short** line's "one playbook there is proven" matches the README's table, where fix a bug is the only proven page (verified).

The page has no `## References` heading.
