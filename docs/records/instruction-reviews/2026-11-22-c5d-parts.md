# Instruction review: docs/parts.md

This records the review of C5d's edits to three rows of the parts table, for its author and its readers.

**In short:** 3 findings: 2 contradiction, 1 enforcement. The `no_force_push` row says `--mirror` is refused with a force, but a plain one is refused. The `push_lease` row's worktree refusal misses `main@{0}` and an earlier checkout in the line. The `git_folder_shell` row says removing a guarded key is refused, but removing the `core` section passes.

## Scope

In scope: in "The parts here", the `push_lease` row, the new `no_force_push` row and the `git_folder_shell` row. The whole page was read. Read beside it: `AGENTS.md`, `INDEX.md`, decision 0004 ("What a push sends" and "The rules the shell guards share"), decision 0005 ("The push guard" and "What a worktree's push sends"), the `no_force_push` entry in `workspace.json`, `wslib/gitrules.py`, `wslib/shellfacts.py`, `parts/no_force_push.py`, `parts/push_lease.py`, `parts/git_folder_shell.py` and their cases files, `tests/test_force_push.py`, `tests/hooks/before-shell.json`, and the plan's C5d row, criteria 36, 38, 55 and 65, and its entry "Three items for slice C5d". Each part's `decide` was called on events whose facts `wslib/shellfacts.py` worked out from real git, in throwaway repositories under a temporary folder: a bare remote, a main copy on `main` and a linked worktree on `feat`. `python3 ws.py selftest` passes for all three parts. Claims that held, verified the same way: `--prune` alone passes; a config write on the push, an unresolved target, a detached HEAD, an alias that runs a shell command and a stored alias that force-pushes main are refused by `no_force_push`, and its cases show `--prune` with a glob or `--all`, and a forced push after a checkout in the line, refused; `git cf core.hooksPath` with `cf = config`, and a non-built-in call with `HOME` or `GIT_CONFIG_GLOBAL` set, are refused by `git_folder_shell`.

## Findings

| # | Class | Where | Finding | Disposition |
|---|---|---|---|---|
| 1 | contradiction | "The parts here", the `no_force_push` row | "`--all`, `--branches` or `--mirror` with a force" reads as a plain `--mirror` passing. Verified: `decide` refuses `git push --mirror origin` with no force. Decision 0004's "What a push sends" says a mirror forces every update, and the part's docstring lists `--mirror`, written or configured, with no force (verified, reading). | fixed: the row lists `--mirror` on its own. |
| 2 | enforcement | "The parts here", the `push_lease` row, "from a linked worktree, a push that sends the branch the main copy has checked out" | The stated refusal is false for forms the guard does not read. It matches the branch by its name in the refspec, works the target out before the line runs, and does not call `earlier_change`. Verified: with the lease held by another live session, `decide` refuses `git push origin main` from the worktree but passes `git push origin main@{0}:refs/heads/x`, a push of main's commit id to a new branch, and `git checkout --ignore-other-worktrees main && git push origin HEAD`. Verified, real git: the first and the third each published the main copy's unpushed commit to the remote. | fixed in part: the reflog form and an earlier checkout or switch are now refused; the row says "named as a branch", and the README's Limits bullet states that a commit named by its id passes. |
| 3 | contradiction | "The parts here", the `git_folder_shell` row, "`git config` sets or removes a key the guards read, such as ... `core.hooksPath`" | Removing the whole `core` section removes those keys and passes. Verified: `decide` passes `git config --remove-section core` and refuses `git config --rename-section foo core`. Verified, real git: `--remove-section core` on a scratch config file dropped `core.worktree`, `core.sshCommand` and `core.hooksPath`. `_guarded` checks `remove-section` against `guarded_key` alone, and C5d added the `core` case to rename only (verified, reading). | fixed: removing the whole `core` section is refused, with a case and a test. |
