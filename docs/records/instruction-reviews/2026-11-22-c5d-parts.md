- finding 2: holds in part, as its disposition says. `main@{0}` forms and a push of HEAD or a bare push after a switch or checkout are refused, the row says "named as a branch", and the README's Limits bullet states that a commit named by its id passes (verified, `decide` and reading). New defects:

- enforcement, "The parts here", the `push_lease` row: its refusal of "a push of HEAD or a bare push after a call earlier in the line that can change the branch" does not hold for HEAD's reflog forms. With the lease `other-live`, `push_lease.decide` from the worktree refuses `git switch --ignore-other-worktrees main && git push origin @` and `git checkout --ignore-other-worktrees main && git push origin HEAD`, but passes `git switch --ignore-other-worktrees main && git push origin 'HEAD@{0}:refs/heads/y'` and the same with `'@{0}:refs/heads/y3'` (verified, `decide`). Real git then created `y` and `y3` on the remote at the main copy's unpushed commit (verified). The cause: `_shared` reads a source as HEAD only when it is `HEAD` or `@` or starts with `HEAD~`, `HEAD^`, `@~` or `@^`, and `HEAD@{0}` cuts to `HEAD`, not the main copy's branch (verified, reading `parts/push_lease.py`). The same reading passes `@{-1}`, the branch checked out before: after the worktree had checked out `main`, `git push origin '@{-1}:refs/heads/z'` passed `decide` and sent the holder's commit (verified). Disposition: fixed. `_shared` in `parts/push_lease.py` reads every source that starts with `HEAD` or `@` as HEAD after an earlier change, and `gitrules.push_updates` leaves a push unresolved when a source names a branch checked out earlier (`@{-N}`), or a reflog entry with no destination, so both guards refuse it; `no_force_push` refuses `git push -f origin @{-1}`. Cases in both parts and in `tests/test_force_push.py`. This was the second fix round on the worktree push, the last the stop rule allows.
