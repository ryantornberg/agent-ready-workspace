Broke:

1. Not blocking. The bullet's sentence "It refuses a push it cannot judge:" opened a list whose items ran to "; and arguments `xargs` supplies." The fix for finding 3 puts a full stop after the first item and a new sentence, "It judges a git call that is not one of git's own commands the same way, ...". The rest of the list, "; a branch or remote written as a variable or a substitution, ... so write `git push -u origin HEAD`; and arguments `xargs` supplies.", now hangs off that new sentence, so it reads as more cases of a git call that is not built in. Verified: the bullet's text against 09e832c. Fix: move the new sentence after the list's last item.

Missed:

1. Blocking. A quoted or escaped program word turns off the B1 refusal. `push_expands` returns early when the text `git` is not in the line (`if "git" not in command.lower() ...`), but the parser and both shells read `g\it`, `gi''t`, `"g"it` and `$'g'it` as `git`. The hook passes `g\it push origin {+,}main`, `gi''t push -f origin mai[n]`, `"g"it push -f origin ma(i)n` and `$'g'it push origin {+,}main`, exit 0 each; `g\it lfs track *.psd` passes too. bash and zsh both print `git git git git +main main` for `g\it gi""t "g"it $'g'it {+,}main`, and run `pr\int`, `"p"rint`, `$'p'rint` and `p''rint` as `print`. Verified: the hook, the two shells, and the early return, which e6b8b6d already held. Inferred, not run: that git then force-pushes main, as finding 1 inferred for the unquoted forms. The bullet and the rules row say this push is refused. Fix: test for `git` after removing quotes and backslashes, or drop the text test and let the walk decide, with cases for each form.
2. Blocking. A remote helper reached through a URL passes every guard. `git -c protocol.ext.allow=always ls-remote 'ext::sh -c git% push% -f% origin% main'` passes the hook, exit 0, and so do the same with `fetch`, with `clone ... x`, and with `GIT_ALLOW_PROTOCOL=ext` in place of `-c`; a `push` to that URL is refused, by `outward_write`. `man git-remote-ext` documents `ext::<command>[ <arguments>...]` with `% ` for a space, and `man git-config` says `protocol.allow` leaves `ext` at `never` unless set, which the line does. Verified: the hook and both man pages. Inferred, not run, since it starts a remote helper: that git runs `sh -c 'git push -f origin main'`. The same line runs any command, such as `gh pr merge 5 --admin`, which the hook also passes (verified). The bullet says a remote helper is refused outright, and the rules row says no force push of main "in any form git offers". Fix: refuse an `ext::` word, or `protocol.ext.allow`, `protocol.allow` or `GIT_ALLOW_PROTOCOL` set on a git call, or name the route among the Limits as an M4 miss.
3. Not blocking. The shell guards bullet names a word followed by `(` "in any command but a git push" as a miss. zsh also runs a qualifier in an array assignment and in a `for` list, which are not commands: `a=(main(e:'print -u2 RAN':))` and `for f in main(e:'print -u2 RAN':); do :; done` each print `RAN` under `zsh -f`, and the hook passes both with a force push of main in the qualifier, exit 0. Verified. The README should say "in any word but one of a git push", or give these forms.
