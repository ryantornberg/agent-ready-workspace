## Findings

| # | Class | Where | Finding | Disposition |
|---|---|---|---|---|
| 1 | enforcement | Limits, the bullet "`no_force_push` judges a push by what git would send" | Blocking. The bullet says the guard refuses "a word of the push that the shell would expand, such as unquoted braces or a glob". The code refuses braces with a comma or `..`, and `*`, `?` and `[`. zsh expands more. `git push -f origin ma(i)n` becomes `main` when a file or folder named `main` is in the folder, and `git push origin feature README.md(e:'git push -f origin main':)` runs the force push while zsh expands the last word. Both pass every before-shell hook. The shell guards' bullet names glob grouping as a miss for a program word only. Verified: the hook, exit 0 on both; `zsh -c` in `/` expands `b(i)n` to `bin` and runs the code in `bin(e:'print -u2 RAN2':)`. Inferred: that the agent's shell is zsh here (`$SHELL` is `/bin/zsh`), and that git then force-pushes main. | fixed, fix round 1: a word directly followed by `(` in a push, or in a git call that may be one, is refused, with cases; the bullet says so. The form in any other command is named in the shell guards bullet as waiting for M4. |
| 2 | enforcement | Limits, the `no_force_push` bullet's sentence on `git send-pack` and `git http-push`; the rules table's `no_force_push` row | Blocking. The bullet names `send-pack` and `http-push` as the commands that push without `git push`, and refuses them. The rules row says no agent force-pushes or deletes main "in any form git offers". `printf 'push +refs/heads/main:refs/heads/main\n\n' \| git remote-https origin https://github.com/ryantornberg/agent-ready-workspace.git` passes every before-shell hook. The parser counts `remote-https` as one of git's own commands, so the bullet's limit for "a program named `git-NAME`" does not name it either. Verified: the hook, exit 0; the helper lists `push` among its capabilities; `man gitremote-helpers` documents a leading `+` as a forced update. Inferred, not run: that the line force-pushes main. | fixed, fix round 1: the remote helpers are refused outright, with cases, and the bullet names them. The rules row's "in any form git offers" stands with the Limits' named exceptions, as before. |
| 3 | contradiction | Limits, the `no_force_push` bullet's sentence on a word the shell would expand | Not blocking. The bullet says the refusal covers "a word of the push", and in the same bullet that the guard "cannot see ... a program named `git-NAME`". The code refuses an unquoted glob or braces in any git call that is not built in, whatever it runs. `git lfs track *.psd` is refused, and so is `git co feature-*` when the alias `co` is read from config as `checkout`. The refusal calls each a push. The part's own docstring still says a subcommand that is neither built in nor an alias "is a program named git-NAME, not a push, and passes". Decision 0004's amendment states the wider rule; this bullet does not, so an agent refused on `git lfs track *.psd` finds no reason here. Verified: the hook refuses `git lfs track *.psd` and passes `git lfs track "*.psd"`; `decide` with the alias read refuses `git co feature-*` and passes `git co feature-x`. | fixed: the bullet says a git call that is not one of git's own commands is judged the same way, with `git lfs track *.psd` refused and its quoted form passing. |
