# Instruction review: README.md

This records the review of C5e's edits to the README's outward-write row, its limits and the adoption steps, for its author and its readers.

**In short:** 5 findings: 3 enforcement, 2 contradiction. A push with `--recurse-submodules` and a push after `gh pr checkout` in the same line pass the guard while writing outside the list. A typed push URL is read without git's `pushInsteadOf`. The list matches a URL by its last two path segments, so a host with deeper paths matches other repositories. The narrowed `git_folder_shell` miss list drops `set-url --delete` and `set-default --unset`.

## Scope

In scope: in "What is checked, and by what", the new row on `outward_write` and `outward_list`; in "## Limits", the new `outward_write` bullet and the `git_folder_shell` bullet's list of known misses; and step 6 under "Use it for your own team". The whole page was read. Read beside it: `AGENTS.md`, `INDEX.md`, decision 0004 with its uncommitted change ("Shell events", "The outward-write guard", the parts table), `docs/parts.md`, `docs/adopt-the-workspace.md`, `workspace.json`, `outward-repos.json`, `parts/outward_write.py`, `parts/outward_list.py` and their cases, `wslib/gitrules.py`, `wslib/shellfacts.py`, `wslib/runner.py` (`shell_event`), `tests/test_outward.py`, `tests/hooks/before-shell.json`, and the M3 plan's C5 row, criteria 39, 55 and 65 and the C5e row of the split. `outward_write.decide` and `git_folder_shell.decide` were called on events `runner.shell_event` worked out from real git, in throwaway repositories under a temporary folder: a repository on `feature` with `origin` at `https://github.com/me/ours.git`, once with a second remote `upstream` at `github.com/them/theirs` and once without, and a list naming `github.com/me/ours`. ## Findings

| # | Class | Where | Finding | Disposition |
|---|---|---|---|---|
| 1 | enforcement | "What is checked, and by what", the `outward_write` row; "## Limits", the `outward_write` bullet | The row says every `git push` to a repository outside the list is refused, but `git push --recurse-submodules=on-demand origin HEAD` passes when `origin` is listed, whatever remotes the submodules push to. The bullet's list of what the guard cannot see does not name it. Verified: `outward_write.decide` passes that command and refuses the same push with `-c push.recurseSubmodules=on-demand`. Verified, real git: in a superproject whose submodule held an unpushed commit, that push sent the commit to the submodule's own remote. The `destinations` fact resolves only the remote the push names (verified, reading `_push_destinations`). In a team's workspace each folder under `src/` is a pinned code repository, which may belong to another team (inferred from `AGENTS.md`, "What lives where"). | fixed: `--recurse-submodules=on-demand` or `only` on the command line is refused, with cases and a real-git test, and the row says so. The Limits bullet names `push.recurseSubmodules` set in config as a miss, since the `destinations` fact reads no config for a named remote. |
| 2 | enforcement | The `outward_write` row; "## Limits", the `outward_write` bullet | `gh pr checkout 5 && git push` passes the guard with `origin` listed. Verified: `decide` passes it, and `gitrules.earlier_change`, which `_push` uses for a push that names no remote, does not name `gh pr checkout` (verified, reading). For a pull request from a fork that lets maintainers edit, `gh pr checkout` sets the new branch's remote and push remote to the fork, so the bare push in the same line writes to the fork (inferred from gh's documented behaviour; not run, since it needs GitHub). Run as two commands, the push is judged on the fork's URL and refused (inferred from `_push_resolved` reading `branch.NAME.pushRemote`). | fixed: a push after a gh call that can add a remote or set an upstream in the same line, `gh pr checkout` or `co`, `gh repo fork`, `set-default` or `clone`, is refused, with cases; the Limits bullet tells the agent to run them one at a time. |
| 3 | contradiction | "## Limits", the `outward_write` bullet, "It reads ... a push's destinations from git, when the command runs" | For a URL typed on the command line the guard does not take git's answer: `_insteadof` in `wslib/shellfacts.py` applies `insteadOf` only, and its docstring says git applies no `pushInsteadOf` to such a URL. Verified, real git 2.50.1: with `url.B.pushInsteadOf=A`, `git push A main:refs/heads/t` created `t` in B and not in A. Verified: with `url.https://github.com/them/theirs.git.pushInsteadOf=/tmp/x.git` set in the repository's config, `decide` passes `git push /tmp/x.git HEAD` as a local path, while the same push writes to `github.com/them/theirs`. An agent cannot set the rule itself, since `git_folder_shell` refuses a URL rewrite and `outward_write` refuses one given with `-c` (verified, reading); a rule a person set is enough. | fixed in code: `_insteadof` in `wslib/shellfacts.py` applies the longest `pushInsteadOf` before the longest `insteadOf` to a typed URL, as git does, with a real-git test. The `no_force_push` target reads the same function, so it is corrected too. Decision 0004's push bullet is amended, and the Limits bullet says what the guard applies. |
| 4 | enforcement | The `outward_write` row; "Use it for your own team", step 6, "each as `HOST/OWNER/NAME`" | A URL is matched by its host and its last two path segments (`_repository` in `wslib/gitrules.py`, verified, reading), so on a host whose paths are deeper the list holds more than it names. Verified, `decide` with the list `gitlab.com/team/app` and `dev.azure.com/_git/app`: `git push https://gitlab.com/othergroup/team/app.git HEAD` passes, a project in another group; and `https://dev.azure.com/otherorg/otherproject/_git/app` passes, any organization's repository named `app`. Verified: listing Azure Repos' full path, `dev.azure.com/myorg/myproject/_git/app`, is not `HOST/OWNER/NAME`, so the whole list becomes unusable and every push to a repository is refused. Step 6 gives no form for such a host, and neither the row nor the Limits bullet says the list assumes two-segment paths. | fixed: a URL matches an entry by its host and its whole path, and an entry may be longer than three parts. Step 6 gives the GitLab subgroup and Azure Repos forms. Cases for a nested group and a real-git test. |
| 5 | contradiction | "## Limits", the `git_folder_shell` bullet, "The known misses are `git remote add` and `set-url` to a listed repository or a local path, since `outward_write` refuses any other URL ... `gh repo set-default` to a listed repository" | The narrowing drops two config changes both guards still pass, which the old wording, `set-url` and `gh repo set-default` with no qualifier, covered. Verified: `outward_write.decide` and `git_folder_shell.decide` both pass `git remote set-url --delete origin https://github.com/them/theirs` and, in a repository with one remote, `gh repo set-default --unset`. Decision 0004 says `set-url --delete` passes `outward_write` (verified, reading). The bullet ends "The list may not be complete", but its new reason, "since `outward_write` refuses any other URL", reads as covering every other form. | fixed: the misses list names `git remote set-url --delete` and `gh repo set-default --unset`, and drops the reason clause that read as covering every other form. |
