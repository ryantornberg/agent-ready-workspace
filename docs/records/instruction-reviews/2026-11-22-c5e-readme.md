# Instruction review: README.md

This records the review of C5e's edits to the README's outward-write row, its limits and the adoption steps, for its author and its readers.

**In short:** 5 findings: 3 enforcement, 2 contradiction. A push with `--recurse-submodules` and a push after `gh pr checkout` in the same line pass the guard while writing outside the list. A typed push URL is read without git's `pushInsteadOf`. The list matches a URL by its last two path segments, so a host with deeper paths matches other repositories. The narrowed `git_folder_shell` miss list drops `set-url --delete` and `set-default --unset`.

In scope: in "What is checked, and by what", the new row on `outward_write` and `outward_list`; in "## Limits", the new `outward_write` bullet and the `git_folder_shell` bullet's list of known misses; and step 6 under "Use it for your own team". The whole page was read. New defects:

- enforcement, "What is checked, and by what", the `outward_write` row, "A push that also pushes submodules on demand is refused"; and "## Limits", the `outward_write` bullet, "It does not read `push.recurseSubmodules` from config". Two forms an agent can type pass the guard and the whole hook chain: `git push --recurse=on-demand origin HEAD`, git's abbreviation of the flag, and `git -c submodule.recurse=true push origin HEAD` (verified, `decide` and `ws.py hook before-shell`, exit 0). Real git, in a superproject whose submodule held an unpushed commit, sent that commit to the submodule's own remote for each form, and for `submodule.recurse=true` set in config (verified). `_recurses` matches only the full flag name, and `config_write` does not hold `submodule.recurse` (verified, reading and `decide`). The bullet names only `push.recurseSubmodules` as the config miss. Disposition: fixed, the second fix round. `_recurses` matches any prefix of `--recurse-submodules` git accepts, from `--recu` on, and `submodule.recurse` or `push.recurseSubmodules` given on the command line; `git_folder_shell` refuses a persistent `submodule.recurse` write, as it refuses `core.hooksPath`. Cases and real-git tests. The row and the Limits bullet name the forms, and the bullet names both keys set in config by a person as misses..
- enforcement, the `outward_write` row, "a `git push`, `git send-pack` or `git http-push` ... is refused". `git send-pack --receive-pack git-receive-pack git@github.com:them/theirs.git main` passes `decide` and the whole hook chain (verified, exit 0). `_plumbing` reads the first word not starting with `-` as the destination, here the option's value, a local path. Real git accepts the option's value as a separate word: `git send-pack --receive-pack git-receive-pack BARE main` created `main` in the bare repository (verified). `--exec` does the same (verified, `decide`). That this form writes to the unlisted GitHub repository over ssh is inferred. Disposition: fixed, the second fix round. `_plumbing` skips the value of `--receive-pack`, `--exec`, `--push-option`, `-o`, `--signed` and `--force-with-lease` written as a separate word, with cases..
- enforcement, "## Limits", the `outward_write` bullet, "`git mv`, `rm`, `checkout` or `restore` naming any file called `outward-repos.json` are refused, while `git apply`, an interpreter and a write through a symbolic link to it are not seen". The list of what is not seen omits git commands that rewrite the list without naming it. `git checkout other -- .`, `git restore --source=other .`, a glob such as `'*.json'`, `git switch other`, `git reset --hard other` and `git merge other` pass `decide` (verified), and `git checkout other -- .` passes the whole hook chain (verified, exit 0). Real git: `git checkout other -- .` replaced the list with the other branch's, which named a second repository (verified). Disposition: fixed, the second fix round. The Limits bullet names `git checkout other -- .`, a pathspec glob, `git switch`, `reset`, `merge` and `apply` as rewriting the list unseen..
