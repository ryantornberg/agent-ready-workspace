# Red team review: docs/plans/m4-fail-closed-guards-review-loop-and-evals.md

A sixteenth fresh red team's attack on M4's draft hand-off plan, checking the claims its decisions rest on against the repository.

**In short:** holds with fixes, 7 findings. The GitHub ruleset of Q109 does not hold against the agent it is named for, and its interaction with the mark's CI step is undecided.

The red team read the plan, the red team review page, the round 15 record, and the sources the plan names, at the commit above, with a clean tree. It also read `wslib/merge.py` (`parse_required`, `judge`), `wslib/lease.py`'s `fast_forward`, `kit/kit.json`, `evals/arms.json`, decision 0011, procedure endings, changing the machinery, the instruction review, and M3's milestone record on the routed arm. It ran `gh api` on this repository's settings, branch protection and rulesets, and `gh auth status` for the sign-in's scopes.

## Verdict

**Holds with fixes.** The core holds: one literal-word rule in the parser, allow lists for git settings and `gh` writes, the grader stamp, staged eval budgets, and a review mark bound to dispatched sessions. The arithmetic of the new budget lines checks out. But the Q109 revision, the newest part of the plan, overclaims what the ruleset holds. The sign-in agents use is a repository admin, so it can delete the ruleset. A pull request's own workflow satisfies the five named checks (finding 1). The plan also never says whether the mark and suite steps are required checks. Either answer breaks something it states (finding 2). G0's rewording leaves the rule that page commits go on local main, which can no longer reach `origin/main` (finding 3).

## What survives

- **`ws.py merge` already reads rulesets.** `parse_required` joins classic protection and the `rules/branches` answer, so a ruleset's required checks are judged with no code change. Verified, by reading `wslib/merge.py`.
- **The five CI checks are what the plan says.** The classic protection requires exactly the five matrix names of the `check` job, with `enforce_admins` off, which is the gap R15-3 named. Verified, by `gh api .../branches/main/protection`.
- **G0 still touches no file the eval hashes.** The guided arm is given `AGENTS.md`, `CLAUDE.md`, `INDEX.md`, `fix-a-bug.md` and the definition of done. Procedure endings, changing the machinery and the parts page are not among them. Verified, by reading `evals/arms.json`.
- **The new budget arithmetic is right.** 135 + 400 + 660 + 45 + 45 + 45 is 1,330; with re-records, 180 + 400 + 660 + 45 + 90 + 90 is 1,465; doubled dispatching baselines add 120, to 1,450. Four recordings bring 1,465 to 1,333, under the stop. Verified, by adding the table's rows.
- **The red team count is right.** Rounds 1 to 15 found 133 findings, as the key point says. Verified, by adding the Red team section's counts.
- **Q110 and Q105 agree.** With no direct push to main, every wrapped-page edit is a pull request, and `suites.py`'s per-branch count of 12 applies to it. The deferred R15-5 is closed by the answer. Verified, by reading Q105, Q110 and the upkeep bullets.
- **The merge-commit rule survives Q109.** `ws.py merge` merges with `--merge --match-head-commit` and checks two parents, which a ruleset does not change. Verified, by reading `build_merge` and the docstring.
- **The plan passes its own checks.** `python3 ws.py check` exits 0 on this tree, with only `eval_record`'s no-base warning. Verified, by running it.
