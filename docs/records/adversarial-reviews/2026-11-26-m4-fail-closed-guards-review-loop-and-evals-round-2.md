# Red team review: docs/plans/m4-fail-closed-guards-review-loop-and-evals.md

A second fresh red team's attack on M4's draft hand-off plan, checking the claims its decisions rest on against the repository.

**In short:** holds with fixes, 14 findings. The core stands, but G2's rule would refuse everyday interpreter commands, the review mark cannot be written in the order the plan sets, and the mark proves less than the plan says.

The red team read the plan and every source it names at the commit above, ran the before-shell hook on crafted command lines, read the stored eval transcripts and records, and counted command shapes in them. It ran no agent, no eval or selection run, and no command a guard judges. Hook probes passed a JSON payload to `python3 ws.py hook before-shell --tool claude-code` and read the exit code; nothing was executed.

## Verdict

**Holds with fixes.** The plan's core still holds: one literal-word rule in the parser, grading files out of the recording's hash, a review loop with a mark and a gate, and staged eval budgets. Findings 1 to 5 must be fixed before approval. G2, as written, parses the code an interpreter is given as a shell line, so it refuses common commands and is likely to change stored grades, which sends the guard slices to the fallback. The review mark's own refusals cannot all be met once the review's record is committed. The mark and the gate prove less than Goal 2 claims. And the upkeep rules contradict each other, so the key point's 44-run figure rarely applies. The rest can be settled without blocking.

## What survives

- **H0a's mechanism holds.** `run.py` builds a record's `covers` and hash through `eval_record.covered_files` and `guidance_hash`, so H0a can move grading files out of the hash without editing `run.py`. The graded hook, `no_stage_all`, imports only `wslib.shell` from the engine, so the grading files the plan names are the ones a grade reads. CI checks out with `fetch-depth: 0` and runs `evals/grade.py --recorded` on every push, so a test that reads H0a's base commit, and the re-grade that guards the stamp, can both run in CI. Verified: `evals/run.py` lines 588 to 595, `parts/no_stage_all.py`'s imports, `.github/workflows/ci.yml` lines 33 and 42.
- **One arm re-recorded alone fits the arms as they are.** The fix-a-bug guided arm is given exactly the contract, the pointer file, the index, `fix-a-bug.md` and the definition of done, plus the order service's rule page for two cases. The two-line arm gets only its two lines, and the bare arm nothing. So slice Z's edits touch the guided arm only, and H0b's item 8 applies to them. Verified: `evals/arms.json` and the cases' `add_files`.
- **The ten pages already have wrappers.** Each of the ten H3 pages has a folder under `plugin/skills/`, so the program's rule that a proven procedure gets its wrapper adds none, and the non-goal of no new wrapper holds. Verified: `plugin/skills/*/SKILL.md`.
- **A suite run of about 6.** 58 selection cases across 28 wrappers is about two cases a wrapper, at three runs each. Verified: `evals/README.md`, "The wrappers' selection cases", and the count of wrapper folders.
- **The proof path is legal under decision 0006.** A baseline written with `--attempt M4` while M4 is in `building` is a failed attempt that licenses one move of `prove-by` to M6, and G0 puts M4 in `building` first. Verified: decision 0006, "Unproven" and its 2026-11-21 amendment.
- **The arithmetic.** Eval runs sum to 1,085 planned and 1,220 with every re-record; review sessions to 186; short runs to 336. M3's 611 agent runs and 249 selection runs match its milestone record. The stored fix-a-bug records each hold 15 runs per arm on one model and one tool version. Verified.
- **Hook behavior the plan relies on.** A write to a `.git` file in a new folder is refused today, by `git_folder_shell`. `gh api` merge calls to an unlisted repository are refused, by `outward_write`. `git -C src/orders-api log` and `GIT_EDITOR=true git rebase --continue` pass today; G3 will have to keep the first passing, since several pages tell agents to run `git -C src/REPO`. Verified, by running the hook and `git grep`.
