# Red team review: docs/plans/m4-fail-closed-guards-review-loop-and-evals.md

A fifth fresh red team's attack on M4's draft hand-off plan, checking the claims its decisions rest on against the repository.

**In short:** holds with fixes, 11 findings. Other `gh api` writes still move main or weaken its branch rule, `HOME` hands git a config that runs a push, and G2 refuses the test-first idiom.

The red team read the plan, the four earlier records and the sources the plan names, at the commit above. It ran the before-shell hook on crafted payloads, a JSON payload passed to `python3 ws.py hook before-shell --tool claude-code`, and read each exit code. It counted the commands stored under `evals/runs/`, read the stored selection results, ran `python3 ws.py check`, and showed with a harmless config in a scratch folder that git reads its global config from `HOME`. Nothing a guard judges was executed: no `gh api` write was sent, and no agent, eval or selection run was started.

## Verdict

**Holds with fixes.** The core still holds. It rests on one literal-word rule in the parser, grading files out of the recording's hash, a review loop with a mark and a gate, and staged eval budgets. Fix findings 1 to 4 before approval. Rows F21 to F23 close three `gh api` endpoints one by one. Other writes of the same kind still move main past every gate, or weaken the branch rule that `ws.py merge` trusts. And F22's fix leaves this repository open. `HOME=DIR git ...` is a force-push route the table does not list. G2's write-path clause would refuse the commands an agent uses to show that a new test fails on the original code. That puts the stop rule's G2 exit within reach. The rest can be settled without blocking.
