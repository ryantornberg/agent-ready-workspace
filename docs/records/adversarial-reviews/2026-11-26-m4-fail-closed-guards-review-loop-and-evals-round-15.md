# Red team review: docs/plans/m4-fail-closed-guards-review-loop-and-evals.md

A fifteenth fresh red team's attack on M4's draft hand-off plan, checking the claims its decisions rest on against the repository.

**In short:** holds with fixes, 8 findings. G2's variable rule reopens a refused force push through `read`, and H0a's stamp is judged by the code it stamps.

The red team read the plan, the red team review page, the round 14 record, and the sources the plan names, at the commit above, with a clean tree. It also read `covered_files`, `guidance_hash` and `judge` in `parts/eval_record.py`, the hashing imports in `evals/run.py`, `regrade_records` and `load_hook` in `evals/grade.py`, `command_push`, `push_parts` and `command_commits` in `wslib/runner.py`, the docstring of `wslib/merge.py`, `evals/arms.json`, `evals/one-time.json`, the debugging and red team cases, the manifest's part entries and tiers, `.githooks/pre-push`, `.claude/settings.json`'s hook wiring, `outward-repos.json`, `.gitignore`, the defect register, M3's milestone record, and the README's guard Limits. It ran the before-shell hook on single events without running the commands it judged; two harmless shell scripts in bash and zsh under the session's scratch folder; the two V8 greps; a pass count of the fix-a-bug records at the tip and at the anchor; and `python3 ws.py check`. It ran no agent, eval or selection run.

## Verdict

**Holds with fixes.** The core holds: one literal-word rule in the parser, allow lists for git settings and `gh` writes, grading files out of the recording's hash, staged eval budgets, and a review mark bound to dispatched sessions. Its arithmetic and its premises about the eval harness check out. But G2's rule for a variable the line sets counts only assignment words, so a builtin that sets the variable afterwards reopens a force push of main that is refused today (finding 1). H0a's stamp lets a change to `grade.py` certify itself, the pattern the plan already fixed for marks and suites (finding 2). And the plan's backstop for row F35 does not hold under the owner's sign-in (finding 3). Each has a local fix or a limit to state; none needs the plan rethought.

| 1 | G2's "A variable the line sets is read with its value" and G3's "A variable set earlier in the line counts as set on the call" name only assignments, and their disqualifiers (`if`, `case`, a loop, a function body, a background job, `&&`, `\|\|`) say nothing of a builtin that sets the variable later. Bash and zsh both let `read`, `printf -v`, a `for` loop variable and `${C:=value}` after `unset` replace a value set by an assignment. So G2, as written, judges `C=echo; read C <<< git; $C push -f origin main` as `echo push -f origin main` and passes it, though the shell force-pushes main. Today that line, and the `printf -v` and `for` forms, are refused, because the program word is a variable. That is a gap the slice causes, so under the stop rule it stops G2.
