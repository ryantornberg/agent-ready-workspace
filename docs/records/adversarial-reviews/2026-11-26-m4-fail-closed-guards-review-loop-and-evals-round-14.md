# Red team review: docs/plans/m4-fail-closed-guards-review-loop-and-evals.md

A fourteenth fresh red team's attack on M4's draft hand-off plan, checking the claims its decisions rest on against the repository.

**In short:** holds with fixes, 6 findings. One edit to the guards' own launcher turns every guard off, and G2's new reading lets a runner add `main` to a push it judged.

The red team read the plan, the round 13 record and the earlier rounds' findings, the red team review page, and the sources the plan names, at the commit above, with a clean tree. It also read `parts/eval_record.py`, the hashing, preparing, settings and flag code in `evals/run.py`, `regrade_records` and `load_hook` in `evals/grade.py`, `parts/wrappers.py`'s waiting rule, `evals/arms.json`, `evals/one-time.json`, the cases under `evals/cases/`, the files under `evals/scaffold/` and `evals/proof/`, the manifest's part entries, `.claude/settings.json`'s hook wiring, `.githooks/pre-push`, `wslib/launch.sh`, and the README's guard table and Limits. It ran the before-shell and before-edit hooks on single events, without running the commands they judged; one tamper test of a guard part and of the launcher in a throwaway local clone under the session's scratch folder, since removed; `python3 ws.py check`; and the Fisher test the gate uses. It ran no agent, eval or selection run.

## Verdict

**Holds with fixes.** The core holds: one literal-word rule in the parser, allow lists for git settings and `gh` writes, grading files out of the recording's hash, staged eval budgets, and a review mark bound to dispatched sessions. Its arithmetic adds up and its eval premise is sound: the eval harness runs no hook, so the parser is grading code only. But the guards the plan relies on to protect the review's evidence can be switched off by one edit to the launcher every hook runs, or by a planted `python3` on the PATH, and no guard or limit names either (finding 1). G2's replacement for the rule that refuses a judged program after an unread one judges only the words it sees, so a runner that adds words from standard input reopens a force push of main that is refused today (finding 2). H2's suite mark has no tie to a run and no guard (finding 3). Each has a local fix or a limit to state.

| 1 | The guards' own trust root is writable by the agent they guard, and the plan neither closes it nor names it. | 2 | G2's new reading after an unread program reopens a force push of main that is refused today, for any runner that adds words to the command it runs. G2 removes "the rule that refused any word naming a judged program after an unread one" and replaces it with a reading that "refuses only a refused command": the words after the unread program are read as git's command, and the line is refused when either reading would be. Standard input is "parsed as a command line". Neither reading sees words the runner appends. So `echo main \| parallel git push -f origin @` is read as `git push -f origin @`, which pushes HEAD from a feature branch and passes, and `main` as a command line, which runs nothing a guard judges; GNU `parallel` then runs `git push -f origin @ main`, a force push of main. `git push -f origin` and `git push -f origin {}` read the same way, with the runner appending or substituting `main`. Today `no_force_push` has a rule for `xargs`, which supplies a push's arguments; G2 states no such rule for the unread runners it now reads through. Criterion 62's F28 case lists `uv run`, `direnv exec` and `parallel ... ::: main`, whose refspecs are all on the line, so the case passes while the route is open. This is a gap the slice causes, so under the stop rule it stops G2. Fix: in G2, a judged program after an unread one is judged as if unknown words may follow its own, so a push there is unresolved unless every word it could be given leaves main untouched. Add row F34 with `echo main \| parallel git push -f origin @` and the `{}` form, refused at G2's base and tip. | Verified, by running the before-shell hook from the branch `m4/plan`: `git push -f origin`, `git push -f origin @` and `git push -f origin {}` exit 0; `echo main \| parallel git push -f origin` and `echo main \| parallel git push -f origin @` exit 2, refused by `git_folder_shell` because `parallel` "may run another program", the rule G2 removes; `echo main \| xargs git push -f origin` and its `-I` forms exit 2, refused by `no_force_push` because `xargs` supplies the push's arguments. Verified, by reading G2's first and fifth bullets, "What goes", and criterion 62. Inferred: that `parallel` appends its input when the command holds no replacement string, from its documented behaviour. | open |

## What survives

- **The eval premise of H0a holds.** `run.py` starts the agent in a fresh repository built from the scaffold and the arm's files, with `--setting-sources project` and no `.claude/` folder in `evals/scaffold/` or `evals/proof/`, so no workspace hook runs during an eval run. The parser touches stored runs only through grading, so moving it to the grader hash cannot hide a change in what an agent met. Verified, by reading `prepare`, `agent_command` and `SETTINGS` in `evals/run.py` and listing both scaffolds.
- **A tampered guard part alone does not pass.** The runner runs a part's cases on every load, so a `decide` that returns nothing refused `git push -f origin main` with "136 of its 189 cases fail". The launcher, which runs before the runner, is the gap in finding 1. Verified, in the throwaway clone.
- **`xargs` stays refused.** Its dedicated rule in `no_force_push` refuses `echo main \| xargs git push -f origin` and its `-I` forms today, and G2's "What goes" does not list it. Verified, by running the hook and reading "What goes".
- **The two-line screen's numbers are right.** At 44 runs an arm, a guided arm at 44 needs two-line at 39 or fewer for p below 0.05, and at 40 it needs 33 or fewer. Verified, by computing `fisher_greater` as `parts/eval_record.py` does.
- **The budget sums add up.** Red team findings 16 + 14 + 12 + 11 + 11 + 8 + 7 + 6 + 8 + 8 + 6 + 7 + 5 = 119; review sessions 18 + 8 + 15 + 52 + 24 + 55 + 15 + 22 + 22 = 231; upkeep 5 × 132 + 135 = 795. Verified, by adding.
- **Slice Z's contract lines have room.** The contract and pointer files hold 5,157 of 6,000 bytes. Verified, by `wc -c` on the four files `loaded_size` names.
- **H3's flag exists.** `run.py --baseline --attempt M4` is accepted today and writes the page, milestone and `not proven` verdict; H0b's item 10 adds the two-line arm and the milestone path. Verified, by reading `plan_runs` and `main` in `evals/run.py`.
- **One-time records cannot block the gate.** `judge` refuses a `one-time` or `baseline` record as passing, and `eval_record` reads only `evals/runs/<case>/record.json`, so `routed-m4` is judged by criterion 51 alone. Verified, by reading `judge` and `run` in `parts/eval_record.py`.
- **The plan passes its own checks.** `python3 ws.py check` exits 0 on this tree, with only `eval_record`'s no-base warning. Verified, by running it.
