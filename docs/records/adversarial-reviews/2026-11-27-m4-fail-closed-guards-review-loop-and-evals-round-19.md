# Red team review: docs/plans/m4-fail-closed-guards-review-loop-and-evals.md

A nineteenth fresh red team's attack on M4's draft hand-off plan, checking the claims its decisions rest on against the repository.

**In short:** holds with fixes, 7 findings. Q110's rule reaches one page only, so procedure endings still sends a wrapped page to main, where H2's hook refuses it. G0's fast path likely misses its 5-minute target on Windows.

The red team read the plan, the red team review page, the round 18 record, and the sources the plan names, at the commit above, with a clean tree. It read the diff of the plan since round 18's commit, `.github/workflows/ci.yml`, `.github/workflows/cold-clone.yml`, `workspace.json`'s `direct_push` and `stop_gate` entries, `wslib/parts.py`, `wslib/runner.py`'s push checks, `parts/` (each hook part's page reads), `tests/hook_cases.py`, and the test modules that name pages. It ran each of the seven `page_tests` modules and the whole unit suite locally with timings, and `gh run view 45942767581 --json jobs` for per-step CI times.

## Verdict

**Holds with fixes.** Round 18's fixes landed where they were aimed. A push to main and the weekly run now always run in full. Criterion 3 holds the event filter. G0's workflow change is in the maintainer's steps. The guards, the harness, the budgets and the review loop are unchanged and still add up. Two things do not yet hold. Q110's new rule is written on changing the machinery alone. Procedure endings' push table, which every procedure ends by, still sends a page commit in the main working copy to main (finding 1). And G0's fast path, as now specified, runs whole test modules: on the local timing, that is about 8 minutes on Windows, past criterion 65's 5 (finding 2). Both are fixable inside H2 and G0. Moving the fast path out of G0 would fix finding 2's slice and finding 3 together.

## What survives

- **Round 18's push and schedule fix holds.** A push to main and the weekly run always run in full, which matches `ci.yml`'s `push: branches: [main]` and `schedule` triggers. A branch push uses `github.event.before`, as `ci.yml` already does for main. Verified, by reading G0 against `ci.yml`.
- **The seven `page_tests` modules are the ones that read this repository's own pages directly.** The other modules that name a page do so in fixtures, in a scratch folder. Verified, by grepping `tests/*.py` for page names and reading each hit outside the seven.
- **No configuration file takes the fast path by being Markdown.** The only tracked `.md` files outside `docs/`, `plugin/`, `evals/`, `src/`, `kit/` and `tests/` are the root pages and `archive/README.md`. `.github/copilot-instructions.md` is under `.github/`, which is machinery. Verified, by `git ls-files '*.md'`.
- **The other round 18 fixes read cleanly.** Criterion 3 holds the event filter. G0 is in the maintainer's steps, with a `prose` rule until L3. The re-check paragraph no longer repeats itself. The Q110 gloss says the suite runs on the author's machine. Verified, by reading the diff since `9b1fadd`.
- **The budget arithmetic is unchanged and right.** 135 + 400 + 660 + 45 + 45 + 45 is 1,330. With re-records, 180 + 400 + 660 + 45 + 90 + 90 is 1,465. Review sessions are 18 + 8 + 15 + 52 + 24 + 55 + 15 + 22 + 22, which is 231. Verified, by adding the tables' rows.
- **The five required jobs are the matrix's five.** Three systems and two Python versions, less Ubuntu on 3.9. Verified, by reading `ci.yml`'s matrix.
