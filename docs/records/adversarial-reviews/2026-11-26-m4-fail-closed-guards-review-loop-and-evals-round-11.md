# Red team review: docs/plans/m4-fail-closed-guards-review-loop-and-evals.md

An eleventh fresh red team's attack on M4's draft hand-off plan, checking the claims its decisions rest on against the repository.

**In short:** holds with fixes, 6 findings. A line can change what a literal word runs, so G2's one rule misses aliases, command hashing and named folders. `git clone --template` runs an agent's hook.

The red team read the plan, the round 10 record, the red team review page and the sources the plan names, at the commit above, with a clean tree. It also read `parts/proof.py`, `building_when_added` in `wslib/snapshot.py`, `parts/handoff_loader.py`, the session-start wiring in `.claude/settings.json`, `parts/no_stage_all.py`'s imports, `load_hook` in `evals/grade.py`, `SETTINGS` and the `--baseline` path in `evals/run.py`, the case files under `evals/cases/`, `evals/arms.json`, the review orchestrator's dimensions and dispatch template, and the `direct_push` and `loaded_size` entries in `workspace.json`. It ran the before-shell hook through `wslib/launch.sh` on about 50 command lines, and `git log` on the ten pages and on the stored baseline records. To test what the shell does, it ran only harmless lines in the agent tool's own shell, each printing text with `echo`, and one `git clone --template` of a scratch repository whose hook wrote a marker file. Nothing a guard judges was executed: no push, no `gh` write, and no agent, eval or selection run.

## Verdict

**Holds with fixes.** The core holds: one literal-word rule in the parser, allow lists for git settings and `gh` writes, grading files out of the recording's hash, staged eval budgets, and a review mark bound to dispatched sessions. But G2 defines "literal" by the text of a word, and a line can change what a literal word means before the shell reads it again (finding 1). G3 misses one more command git itself runs, during a clone (finding 2). Both give a force push of main past every guard today, and as G2 and G3 are written, after them too. Finding 3 would block H3's first page at the proof check. Finding 4 breaks the claim that dispatch holds the fresh-context rule by itself. Each has a local fix.

## What survives

- **The common spellings of a program word are judged.** `\git`, `/usr/bin/git`, `exec git`, `GIT`, `command git` and `nohup git`, each with `push -f origin main`, exit 2 at the before-shell hook. Verified, by running it.
- **The other line-level mechanisms tried hold today.** A function that pushes (`f() { git push -f origin main; }; f`), a git alias given with `-c`, a `git config alias.p` write, a write to `~/.gitconfig` or `~/.config/git/config`, `printf main | xargs git push -f origin`, `eval 'git push -f origin main'`, `--mirror` and `--all -f` are each refused. Verified, by running the hook.
- **A recording cannot see the guards.** `run.py` gives the agent project settings only, from `SETTINGS`, which hold a sandbox and no hooks. The scaffold holds no `.claude/` folder. So G2 to G4 change no agent's behavior in a run, and only the re-grade can move a grade, as H0a assumes. Verified, by reading `run.py` and listing `evals/scaffold`.
- **H0a's grading-file set is complete for the fix-a-bug cases.** `no_stage_all` imports only `wslib.shell`, `wslib/shell.py` imports only the standard library, and `grade.py` loads the hook from `parts/`. Verified, by reading the three.
- **Slice Z's contract and index edits stale no H3 record.** The proof cases give their guided arm a frozen contract copy from `evals/proof/<page>/contract.md`, so criterion 30 and Z do not collide. Verified, for debugging's and red team review's cases.
