# Red team review: docs/plans/m4-fail-closed-guards-review-loop-and-evals.md

An eighteenth fresh red team's attack on M4's draft hand-off plan, checking the claims its decisions rest on against the repository.

**In short:** holds with fixes, 7 findings. G0's fast CI path, kept after Q114, serves almost no pull request once H2 lands, and it skips unit tests that judge pages.

The red team read the plan, the red team review page, the round 17 record, and the sources the plan names, at the commit above, with a clean tree. It also read the diff of the plan since round 17's commit, `workspace.json`'s `direct_push` entry, `wslib/merge.py`'s `judge` and `merge`, `wslib/parts.py`'s phases, and the unit tests that read pages: `tests/test_core.py`, `tests/test_kit.py`, `tests/test_m3_b7.py`, `tests/test_instruction_review.py`, `tests/test_m3_a.py`, `tests/test_tutorials.py` and `tests/test_cold_clone.py`. It ran `gh run list` and `gh run view --json jobs` for per-step CI times.

## Verdict

**Holds with fixes.** The Q114 revision is clean where it matters most. The identity split is gone from G0, criterion 64 and the maintainer's steps. The re-check paragraph and row F35 now say plainly that nothing in the repository stops an agent that turns its own guards off. The guards, the harness, the budgets and the review loop are unchanged since round 17 and still add up. What does not yet hold is G0's fast CI path. It was introduced for Q113's agent page pull requests, which Q114 deferred. As specified, it will not serve the wrapped-page pull requests it now names, since each carries a suite mark under `evals/` (finding 1). It skips unit tests that judge pages (finding 2). Its push-run classing would put main itself on the fast path (finding 3). All are fixable inside G0. Q110 has no slice, criterion or check behind it (finding 4).

## What survives

- **The Q114 revision reads cleanly.** No slice, criterion or step still assumes the identity split. The R16 and R17 rows marked "Settled by Q114" match the text. Criterion 64 now checks only what Q114 asks: that the README and row F35 name the route and M10. Verified, by grepping the plan for `identity`, `Q113`, `non-admin`, `branch rule` and `straight to main`, and reading each hit.
- **The fast path meets its time target when it applies.** In the last full run on `m4/plan`, every step but the unit tests and `hook_cases.py` took at most 37 seconds on any system, Python's setup included. The selftest, the re-grade, the history scan, the commit checks and the CI-phase check each took 7 seconds or less on Windows. So criterion 65's "under 5 minutes" is reachable. Verified, by `gh run view 45942767581 --json jobs` (Windows 3.13: unit tests 1,225 s, `hook_cases.py` 672 s, every other step at most 7 s).
- **R17-3's remedy holds for the folders it names.** The fast path still runs `grade.py --recorded`, the history secret scan and `ws.py check --phase ci`, and a range under `plugin/`, `evals/` or `src/` runs everything. Verified, by reading G0 against `ci.yml`'s steps.
- **R17-4's remedy holds for the list and the classing code.** Both are read from the base commit with `git show`, so a pull request cannot edit them to widen its own path. Only the workflow file itself stays open, as finding 5 says. Verified, by reading G0 and L3.
- **The budget arithmetic is right.** 135 + 400 + 660 + 45 + 45 + 45 is 1,330. With re-records, 180 + 400 + 660 + 45 + 90 + 90 is 1,465. Review sessions are 18 + 8 + 15 + 52 + 24 + 55 + 15 + 22 + 22, which is 231. Verified, by adding the tables' rows.
- **The F35 limit is now stated truthfully.** The re-check paragraph says that nothing in the repository stops an agent that edits the launcher. It also says that the branch rule does not bind the owner's sign-in that agents use. Verified, by reading the paragraph; round 17 verified the sign-in.
