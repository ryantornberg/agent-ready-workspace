# Red team review: docs/plans/m4-fail-closed-guards-review-loop-and-evals.md

An eighth fresh red team's attack on M4's draft hand-off plan, checking the claims its decisions rest on against the repository.

**In short:** holds with fixes, 6 findings. H3's new two-line screen runs before the cut rule, so a page the bare model already does is never cut. Replacing a case breaks criterion 30.

The red team read the plan, the seven earlier records and the sources the plan names, at the commit above, with a clean tree. It read `evals/run.py`'s `plan_runs` and `main`, `parts/eval_record.py` in full, `parts/proof.py`'s `failed_attempts`, `evals/arms.json`, `evals/one-time.json`, every case under `evals/cases/`, `parts/no_stage_all.py`'s imports, `wslib/parts.py`'s `NEEDS` and `TOP_LEVEL`, `wslib/runner.py`'s `push_parts` and `command_push`, `.githooks/pre-push`, `.github/workflows/ci.yml`, `.claude/settings.json`'s hooks, decision 0006, the machinery page's table and traps, `docs/parts.md`'s headings and its parts table, the README's guard rows and limits, orchestration's limits, the review orchestrator's dimensions, and the tests that read the machinery table and each part's `PAGE`. It ran `python3 ws.py check`, V8's first grep, `fisher_greater` for the screen's thresholds, `git grep` for links into `docs/parts.md` and `docs/changing-the-machinery.md`, `git config --local --list`, and one read-only `gh api` GET of main's protection. Nothing a guard judges was executed: no push, no `gh` write, and no agent, eval or selection run.

## Verdict

**Holds with fixes.** The core holds: one literal-word rule in the parser, grading files out of the recording's hash, a review loop with a mark and a gate, and staged eval budgets. Round 7's fixes are buildable as written, with two exceptions that need a decision before approval. Finding 1: the two-line screen sits in front of the cut table, so the cut decision 0006 requires never fires for a page the bare model already does. Finding 2: H3's replace-a-case row needs a commit that criterion 30 forbids. Finding 3 turns a claim about CI into a limit the README must name. The rest can be settled without blocking.

## What survives

- **R7-1's fix can be built where the plan puts it.** Today `plan_runs` gives `--baseline` the bare arm alone and writes `kind`, `page`, `milestone` and the verdict `not proven` with `--attempt`. That is the shape `failed_attempts` in `parts/proof.py` reads, so adding the two-line arm before the freeze changes no proof rule. Verified, by reading both.
- **R7-5's placements fit the engine.** `TOP_LEVEL` holds `version`, `tiers`, `parts`, `retired` and `building`, and a part's config is its entry less `use` and `why`, so the cap, the merge policy and the eval model each fit a part's entry. `NEEDS` gives `own_edits` to `stop` alone, as the plan now says before amending decision 0004. Verified, by reading `wslib/parts.py` and the parts page's "Adding a part".

So the grading files are `grade.py`, `parts/no_stage_all.py` and `wslib/shell.py`, as H0a lists them. `run.py` imports `grade`, `proofkeys` and `eval_record`, and the hash is built in `eval_record`'s `covered_files`, which `run.py` calls. So moving files between hashes needs no change to `run.py`. Verified, by reading the cases, the imports and `covered`.
- **The pre-push check already takes its parts from the remote's tip**, as L3's comparison says. Verified, by reading `push_parts` and `command_push` in `wslib/runner.py`.
- **The fix-a-bug records are current at the reviewed commit.** Verified: `python3 ws.py check` exits 0, with only the warning that a plain check has no base commit.
- **Main's protection is as round 7 recorded it:** five required contexts, `enforce_admins` false. Verified, by a read-only `gh api` GET.
