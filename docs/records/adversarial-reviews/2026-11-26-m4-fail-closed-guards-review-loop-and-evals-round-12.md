# Red team review: docs/plans/m4-fail-closed-guards-review-loop-and-evals.md

A twelfth fresh red team's attack on M4's draft hand-off plan, checking the claims its decisions rest on against the repository.

**In short:** holds with fixes, 7 findings. G2's rule that reads a variable as its value would pass force pushes refused today, and a shell's `/dev/stdin` or process-substitution operand runs text no guard reads.

The red team read the plan, the round 11 record, the red team review page and the sources the plan names, at the commit above, with a clean tree. It also read `covered_files` and `HARNESS` in `parts/eval_record.py`, `failed_attempts` in `parts/proof.py`, the shell handling and the `env` model in `wslib/shell.py`, `command_push` and `command_commits` in `wslib/runner.py`, `wslib/launch.sh`, `wslib/start.py`'s header, `evals/arms.json`, `evals/cases/fix-a-bug.json`, the manifest's `direct_push`, `wrappers` and `eval_record` entries, `outward-repos.json`, and the README's guard limits. It ran the before-shell hook through `wslib/launch.sh`, with a Claude Code payload, on about 45 command lines, and called `wslib.shell.analyze` directly on 13 lines to read its `env` facts. To test what the shells do, it ran only harmless lines in bash 3.2 and zsh 5.9, each printing text with `echo` or `printf`. Nothing a guard judges was executed: no push, no `gh` write, no ledger close, and no agent, eval or selection run.

## Verdict

**Holds with fixes.** The core holds: one literal-word rule in the parser, allow lists for git settings and `gh` writes, grading files out of the recording's hash, staged eval budgets, and a review mark bound to dispatched sessions. But the bullet that reads a variable as its value rests on a parser model that keeps the last assignment written, not the one that runs, so G2 and G3 as written would pass lines that are refused today (finding 1). Two shell forms run text the line holds and pass every guard today, and G2's wording does not reach them (finding 2). The person-only commands the plan guards by their `ws.py` spelling have a second, documented spelling (finding 3). Findings 4 and 5 leave the review mark's two central claims, that the review ran and that CI checks its mark, open to a builder's reading. Each has a local fix.

| 1 | G2's bullet "A variable the line sets is read with its value" turns a refusal into a pass. Today a program word that is a variable is refused wherever it runs, as the README says. The parser's `env` model, which G3 also leans on ("the parser already carries an export into the commands after it"), keeps the last assignment written in the line, whether or not it runs, and ignores that a background group or a function body does not change the parent shell. So `if [ -d / ]; then C=git; else C=echo; fi; $C push -f origin main`, `C=git; [ -d /nonexistent ] && C=echo; $C push -f origin main`, `C=git; { C=echo; } & $C push -f origin main` and `C=git; f() { C=echo; }; $C push -f origin main` would be judged as `echo push ...` and pass, while the shell runs `git push`. G3 has the same gap the other way round: `export GIT_EDITOR='...'; [ -d /nonexistent ] && export GIT_EDITOR=true; git commit --amend` would be judged on the safe value `true`. This is a gap the slice causes, under the stop rule's own split. Fix: a variable counts as set only when every assignment to it before the word runs unconditionally in the same shell: not inside `if`, `case`, a loop, a function body, a background job, or after `&&` or `\|\|`. Otherwise the word stays not literal, and for G3 each value the line could leave is judged, refusing if any is refused. Add the four lines above, and the `GIT_EDITOR` line, as cases. | Verified, by running the before-shell hook: the first three lines exit 2 today, "the program is a variable or substitution". Verified, by calling `wslib.shell.analyze`: its `env` gives `C` as `echo` for the `if`/`else` line, the `&& C=echo` line after `[ -d /nonexistent ]`, the background group and the uncalled function body. Verified, in bash and zsh with `printf` standing in for git: the `if` branch's value runs, and after `{ C=echo; } & wait` the parent's value runs. Verified, by reading G2's bullet and G3's export bullet. Inferred: that a builder would reuse the existing `env` model, since G3 names it as the basis. | open |
| 2 | Four forms run text the line itself holds, pass every guard today, and are no row of the force-push table: `bash /dev/stdin <<< 'git push -f origin main'`, `bash <(echo 'git push -f origin main')`, `source <(echo 'git push -f origin main')` and zsh's `. =(echo 'git push -f origin main')`. `echo 'git push -f origin main' \| source /dev/stdin` and `source /dev/stdin` with a heredoc pass too. The parser treats a shell's first operand as a script, out of reach, before it looks at a here-string, so the operand `/dev/stdin` hides the text; and it does not count `source` or `.` as a shell. G2's standard-input bullet covers text redirected into "a program the parser does not read", which reaches the two `source` forms. It does not reach `bash /dev/stdin <<<`, since bash is a program the parser reads, and its claim that this works "as text piped into a shell is today" is false for that form. Nor does any bullet make a shell's or `source`'s script operand a deciding word, so a process substitution there is judged only as a possible program name, and `echo`'s quoted text inside it is never read. Fix: a shell's or `source`'s script operand is a deciding word; `/dev/stdin`, `/dev/fd/N` and `-` there read the redirected text as G2's stdin bullet does; a process substitution there, `<(...)` or `=(...)`, is read as the text its command prints when that command is a never-run program with literal arguments, and is unresolved otherwise. Add a row for each form, with cases, and say in the README's Limits that a script file written earlier is still out of reach. | Verified, by running the before-shell hook: each of the six lines exits 0; `zsh <<< '...'` and `echo '...' \| sh` exit 2. Verified, in bash 3.2 and zsh 5.9 with `echo` text only: each form runs the text it is given. Verified, by reading `wslib/shell.py`: `if i < len(args) and not reads_stdin: return emit(name)  # a script: out of reach`, ahead of the here-string branch, and `SHELLS`, which holds no `source` or `.`. Verified, by reading G2's bullets and rows F11 to F32. Inferred: how G2 as written would judge each form, since it is not built. | open |
