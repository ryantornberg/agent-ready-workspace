# Red team review: docs/plans/m4-fail-closed-guards-review-loop-and-evals.md

A seventeenth fresh red team's attack on M4's draft hand-off plan, checking the claims its decisions rest on against the repository.

**In short:** holds with fixes, 10 findings. Q113's agent identity binds only an agent that chooses to use it, and G0's fast CI path skips the gates that judge page-only ranges.

The red team read the plan, the red team review page, the round 16 record, and the sources the plan names, at the commit above, with a clean tree. It also read `parts/direct_push.py` and its manifest entry, `parts/no_admin_merge.py`, `parts/secret_scan.py`, `wslib/merge.py`, `wslib/lease.py`'s `fast_forward`, `wslib/parts.py`'s default phases, `.claude/settings.json`, `evals/arms.json`, `evals/one-time.json`, decision 0011 and procedure endings. It ran the before-shell hook on seven lines, criterion 64's grep, `git config remote.origin.url`, `gh auth status`, and `gh run list` for CI durations.

## Verdict

**Holds with fixes.** The core holds: one literal-word rule in the parser, allow lists for git settings and `gh` writes, the grader stamp, staged eval budgets, and a review mark bound to dispatched sessions. The budget and session arithmetic still adds up. The Q113 revision, the newest part, does not yet hold as written. Agents run as the maintainer's own OS user, so his SSH key and his admin `gh` sign-in stay in reach, and nothing in the plan makes an agent push as the new identity (finding 1). Neither identity option the plan offers meets all three things it claims (finding 2). G0's fast CI path skips the suite step, the re-grade and the history secret scan, which are the CI gates that judge page-only and record-only ranges (finding 3). All three are fixable inside G0 and the F35 paragraph.

## What survives

- **The budget arithmetic is right.** 135 + 400 + 660 + 45 + 45 + 45 is 1,330. With re-records, 180 + 400 + 660 + 45 + 90 + 90 is 1,465. Review sessions are 18 + 8 + 15 + 52 + 24 + 55 + 15 + 22 + 22, which is 231. Verified, by adding the tables' rows.
- **G0 still touches no file the guided arm is given.** The guided arm gets `AGENTS.md`, `CLAUDE.md`, `INDEX.md`, `fix-a-bug.md` and the definition of done. Procedure endings, changing the machinery, the parts page, extend the workspace and the adoption page are not among them. The routed arms read every linked page, but `eval_record` never counts a one-time record as passing, so G0's edits gate nothing. Verified, by reading `evals/arms.json`, `evals/one-time.json` and `eval_record`'s handling of `kind` `one-time`.
- **The fast path runs `eval_record` and `proof`.** Both run in the `ci` phase by default, so `ws.py check --phase ci` still gates a proven page or a proof anchor on the fast path. Verified, by reading `DEFAULT_PHASES` in `wslib/parts.py` and the absence of a `PHASES` line in `parts/eval_record.py`.
- **`ws.py merge` reads the branch rule without the admin-only endpoint.** It reads `branches/BRANCH` and `rules/branches/BRANCH`, not `branches/BRANCH/protection`, so a non-admin identity can still learn the required checks. Verified, by reading `build_branch_rule` and `build_rulesets`. Inferred: that the branch answer carries `required_status_checks` for a reader without admin rights.
- **The guards already refuse an agent's sign-in change.** `gh auth switch`, `gh auth login` and a `git config` write of `remote.origin.pushurl` are refused by the hook today. Verified, by running the before-shell hook.
- **R16-1's two halves are answered in intent.** A non-admin identity cannot edit the branch rule, and an identity without workflow permission cannot push a workflow change. Findings 1 and 2 attack only whether the plan's setup gives agents that identity and no other.
