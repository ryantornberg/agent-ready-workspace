# Red team review: docs/plans/m4-fail-closed-guards-review-loop-and-evals.md

A sixth fresh red team's attack on M4's draft hand-off plan, checking the claims its decisions rest on against the repository.

**In short:** holds with fixes, 8 findings. G2 removes the only rule that refuses `uv run git push -f origin main`, and `gh` commands other than `gh api` still change the listed repository's default branch and settings.

The red team read the plan, the five earlier records and the sources the plan names, at the commit above. It ran the before-shell and before-edit hooks on crafted payloads, a JSON payload passed to `python3 ws.py hook before-shell --tool claude-code`, and read each exit code and refusal. It read `.github/workflows/ci.yml`, `.claude/settings.json`, `.githooks/pre-commit`, `parts/eval_record.py`'s `judge`, `pooled` and `covered_files`, the dispatch templates in the review orchestrator and red team review pages, and `kit/kit.json`. It computed the Fisher test's thresholds with `fisher_greater`, and counted commits per page with `git log`. It read the token's scopes with `gh auth status`. Nothing a guard judges was executed: no push, no `gh` write, and no agent, eval or selection run.

## Verdict

**Holds with fixes.** The core still holds: one literal-word rule in the parser, grading files out of the recording's hash, a review loop with a mark and a gate, and staged eval budgets. Fix findings 1 and 2 before approval. As written, G2 deletes the stopgap that today refuses a force push behind any program the parser does not read, and none of G2's new cases replaces it. That reopens a blocking route, which the stop rule counts as caused by the slice. G4 turns `gh api` writes into an allow list, but the same writes made through `gh repo edit` and other `gh` subcommands pass on the listed repository today and after G4. Finding 3 needs a decision or a named limit: every gate a pull request must pass runs that pull request's own code. The rest can be settled without blocking.

## What survives

- **The commit counts behind H3's high-churn rule are right.** `parts.md` changed in 55 commits and `changing-the-machinery.md` in 22, and the other eight pages in 1 to 6. Verified, `git log --oneline origin/main -- PATH` per page.
- **H3's decision table now matches `judge`.** A record fails unless, in each case, guided passes more often than bare. Recording only at 5 or fewer in one case and 7 or fewer in the other leaves room to win. Verified, `parts/eval_record.py`.
- **Most force-push forms do not rest on the stopgap that finding 1 is about.** `+HEAD:main`, `--mirror`, `-f --all`, `git send-pack --force`, arguments that `xargs` supplies, and the runners `nice`, `stdbuf`, `caffeinate`, `chronic` and `unbuffer` are refused by `no_force_push` itself. Verified, by running the hook.
- **Hooks enter the eval's hash only through `no_stage_all` and the parser.** Every hook grader in `evals/cases/` names `no_stage_all`, and `covered_files` adds `parts/<hook>.py` and `wslib/shell.py` only for those. So G3's and G4's part changes outside the parser touch no record. Verified, by grep and reading.
- **CI can read a mark's ancestry and patch id.** Its checkout uses `fetch-depth: 0`. Verified, the checkout step of `.github/workflows/ci.yml`.
- **The 30-minute reviewer limit is sourced.** Decision 0020's row 7 sets one limit of 30 minutes for every reviewer, and says no page holds it yet. Verified.
- **Q106 agrees with the workspace's limits.** Orchestration's "Limits" says an attended review loop has no fixed round count and ends on a round that only finishes earlier work. Verified.
- **The arithmetic holds.** Eval runs are 1,085 planned and 1,220 with re-records; 1,745 and 1,880 if all ten pages were recorded. Review sessions sum to 217. Verified, by adding the tables.
- **`gh repo delete` cannot run on the current token.** Its scopes hold no `delete_repo`. Verified, `gh auth status`; that GitHub then refuses the call is inferred.
