# Red team review: docs/plans/m4-fail-closed-guards-review-loop-and-evals.md

A fresh red team's attack on M4's draft hand-off plan, checking the claims its decisions rest on against the repository.

**In short:** holds with fixes, 16 findings. The guard rule, the grader split and the budgets mostly stand, but the review mark cannot sit at the tip it reviewed, and the suite gate fails four wrappers today.

The red team read the plan and every source it names at the commit above, ran the before-shell hook on crafted command lines, and computed which stored eval records are current. It ran no agent, no eval or selection run, and no command a guard judges. Hook probes passed a JSON payload to `python3 ws.py hook before-shell --tool claude-code` and read the exit code; nothing was executed.

## Verdict

**Holds with fixes.** The plan's core holds: one literal-word rule in the parser, grading files out of the recording's hash, and a review loop with a mark and a gate. The checks below show the H0a premise is sound and the budget arithmetic adds up. Findings 1 to 4 must be fixed before approval. As written, the review mark cannot sit at the commit the plan's own record rule creates. The suite gate cannot pass four wrappers that miss today. The mark rests on a file the reviewed agent can write. And "fails closed" leaves routes the rule does not reach. Finding 5 makes a criterion impossible to meet. The rest can be settled without blocking.

## What survives

- **H0a's premise holds.** Hooks do not run during an eval run, so the parser and the graded hook are grading files only. The scaffolds hold no `.claude` settings, and `run.py` starts the agent with `--setting-sources project` and its own sandbox settings. `grade.py` is called only after a run, on its transcript. `run.py` builds its hash through `eval_record.covered_files` and `guidance_hash`, so H0a can change what is hashed without editing `run.py`. Verified, by reading `evals/run.py` and `parts/eval_record.py`, and `git ls-files evals/scaffold evals/proof`.
- **The force-push rows are real.** F1 to F16 and F18, with the `...` filled with the push F1 shows, each exit 0 at the before-shell hook today. A plain `git push -f origin main` and the rows' cousins the parser reads are refused. F17 as reconstructed was refused by another rule, so the row's exact line could not be checked. `which git` and `grep -n git notes.txt` are refused today, and `ls *.md` and `command -v git` pass, as G2 says. Verified, by running the hook.
- **The red team triage item's facts.** Size the work names the plan's table in three places. Both hidden tests assert a Disposition in the plan's table. Red team review is unproven, and `eval_record` gates only proven pages. Verified.
- **The defect rows G0 closes exist,** with `building` still `["M3"]` while M3's record says `status: signed off`, and `.env` not ignored. Verified: `docs/records/defects.md`, `workspace.json` and `docs/milestones/m3.md`.
- **The arithmetic.** Eval runs sum to 1,085 planned and 1,220 with every re-record. Review sessions sum to 180. The upkeep figures, 44 a page and 45 for fix-a-bug, follow from 22 runs per case and 15 per case. Criterion 20's figures match the eval page: R2 at 42 of 45, the anchor at 40, and 78 of 90 at a margin of 6. Verified.
- **Other cited facts.** Decision 0020 sets 30 minutes per reviewer and says no page holds it yet. Ten pages or sections name M4 in `prove-by`. `parts.md` changed in 55 commits on main and `changing-the-machinery.md` in 22. The review page runs five dimensions always. The kit's pages are not gated in an instance. Verified.
- **Two notes, not findings.** The worker tier is the same model as the driver at lower effort (`workspace.json`), so the Q91 saving is in effort only. `check --commits` runs message checks only, so the `--no-verify` route for H0b's commits works as the machinery page says. Verified.
