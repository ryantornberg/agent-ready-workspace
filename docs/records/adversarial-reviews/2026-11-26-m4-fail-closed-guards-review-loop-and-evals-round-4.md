# Red team review: docs/plans/m4-fail-closed-guards-review-loop-and-evals.md

A fourth fresh red team's attack on M4's draft hand-off plan, checking the claims its decisions rest on against the repository.

**In short:** holds with fixes, 11 findings. `gh api` can force-move main and merge past CI with no guard in the way, a git folder made and written in one line evades G3 and G4, and H2's suite mark breaks decision 0006's proof-key design.

The red team read the plan, the three earlier records and the sources the plan names, at the commit above. It ran the before-shell and before-edit hooks on crafted payloads, recomputed every stored record's hash through `run.py`'s own `covered`, ran `python3 ws.py check`, counted commits with `git log origin/main`, and read main's branch protection with `gh api` GET calls. Hook probes passed a JSON payload to `python3 ws.py hook before-shell --tool claude-code` and read the exit code. Nothing a guard judges was executed, and no agent, eval or selection run was started.

## Verdict

**Holds with fixes.** The core still holds. It rests on one literal-word rule in the parser, grading files out of the recording's hash, a review loop with a mark and a gate, and staged eval budgets. Findings 1 to 3 must be fixed before approval. Three REST routes through `gh api` reach main with no guard in the way. Two of them are the force-push and admin-merge routes the guards exist to refuse. No slice closes them, and no row or Limits line names them. A git folder made and written in the same line passes today, and G3's "known folder" wording would let a later call run its config. H2's suite mark fingerprints pages by git object id and folds outcome cases into suites. So a proof-key edit, or any edit to an unproven page that has outcome cases, needs outcome runs at the head, which nothing budgets or defines. The rest can be settled without blocking.

## What survives

- **H0a's premise holds.** Recomputed through `run.py`'s own `covered`, the three fix-a-bug records are current and the five debugging and red team records are stale, as the plan says. `run.py` builds its hash through `eval_record.covered_files`, so H0a can move grading files out of the hash without editing `run.py`. Verified.
- **Criterion 20's numbers are right.** R2's guided arm passed 42 of 45 and the anchor 40. On the 90-run scale, 84 less a margin of 6 is 78. Verified, `evals/README.md` and `fix-a-bug.md`'s `proven-by`.
- **The churn and history figures are right.** `parts.md` changed in 55 commits, `changing-the-machinery.md` in 22, and the other pages in 1 to 6. M3 used 611 agent runs and 249 selection runs. Verified, `git log origin/main` and `docs/milestones/m3.md`.
- **G0's three defect rows exist as described:** `building` pinned to M3 by a test, `.env` not ignored, and model names outside the binding. M3's record has `status: signed off`. Verified, `docs/records/defects.md` and `docs/milestones/m3.md`.
- **No rebase loop on the mark.** Main's branch rule does not require a branch to be up to date (`strict` is false), so a marked branch is not forced into `rebased` or `delta` before every merge. Verified, `gh api` GET.
- **L7's `lifecycle_map` check starts green.** Every playbook and how-to under `docs/` already has a row on the lifecycle map. Verified, by script.
- **Decision 0020's 30-minute limit is as cited.** Verified, row 7.
- **The arithmetic and budgets hold.** The eval-run table sums to 1,085 and 1,220, and the review-session table to 216. The Key points hold 196 words, and no table cell passes 60. `python3 ws.py check` passes, with only the no-base warning. Verified.
- **Branch tooling holds against the routes it names.** `gh pr merge 5 --admin` and `gh repo edit --default-branch` are refused, and a `.git` segment in a write is refused. Verified, by running the hook.
